一、项目概述

在工控（SCADA / DCS / PLC）系统中，报警管理是操作员最核心的交互界面之一。 本系统将现有的简易报警面板改造为符合行业标准的报警管理模块，涵盖报警产生、确认、恢复、 归档、统计全生命周期。

📐 设计原则

  • 少即是多 — 只展示操作员需要行动的报警，避免报警洪流
  • 可见性优先 — 未确认的严重报警必须有强烈的视觉提示（闪烁）
  • 追责可溯 — 谁在什么时候确认/搁置了报警，留痕
  • 顺手导出 — 一键导出 CSV，方便对接第三方分析工具
  • 不死数据 — 重启程序不丢历史报警，自动持久化
  • 规则即文件 — 默认规则以应用自带 JSON 文件发布，不硬编码在代码中

🔑 关键概念：什么是"好报警"？

ISA 18.2 定义：报警是"向操作员指示设备故障、过程偏差或异常情况，需要及时响应的可听/可视手段"

一个好的报警必须同时满足：

  • 相关 — 不是正常工况的确认信息
  • 唯一 — 不与其他报警重复
  • 及时 — 有足够响应时间
  • 有优先级 — 区分重要程度
  • 可理解 — 信息清晰明确
  • 有诊断性 — 能定位问题原因
  • 有建议动作 — 告诉操作员该做什么

Warning警告黄色操作员知情

AlarmConditionType (新增)

枚举值含义触发条件
High高限 (HI)值 > 阈值
HighHigh高高限 (HIHI)值 >> 阈值 (比 HI 更严重)
Low低限 (LO)值 < 阈值
LowLow低低限 (LOLO)值 << 阈值
NotEqual不等于 (数字故障)值 ≠ 阈值 (允许 ±容忍度)
RateOfChange变化率|dv/dt| > 阈值
Digital数字量状态布尔位 = 触发值

AlarmItem (核心模型)

public partial class AlarmItem : ObservableObject
{
    // ========== 不可变属性 (Init-only) ==========
    public DateTime        Timestamp     { get; init; }  // 产生时间
    public AlarmSeverity   Severity      { get; init; }  // 严重度
    public AlarmConditionType AlarmType  { get; init; }  // 报警类型
    public string          VariableName  { get; init; }  // 变量名 (I0, Q5...)
    public string          Description   { get; init; }  // 描述文本
    public string          Area          { get; init; }  // 所属区域
    public double          CurrentValue  { get; init; }  // 触发时刻值
    public double?         Threshold     { get; init; }  // 阈值
    public double          Deadband      { get; init; }  // 死区宽度

    // ========== 可变属性 (ObservableProperty) ==========
    bool _isActive;          // 报警是否活动
    bool _isAcknowledged;    // 是否已确认
    bool _isShelved;         // 是否已搁置
    string? _acknowledgedBy; // 确认人
    string? _shelvedBy;      // 搁置人
    DateTime? _acknowledgedAt;   // 确认时间
    DateTime? _shelvedUntil;     // 搁置到期
    string? _comment;           // 操作员备注

    // ========== 计算属性 ==========
    string  TimeText    => Timestamp.ToString("HH:mm:ss");
    string  StatusText  => (IsActive, IsAcknowledged, IsShelved) switch { ... };
    TimeSpan? Duration  => IsActive ? DateTime.Now - Timestamp : null;
}

PollingStore — 全局响应式轮询状态

PollingScheduler 的状态（是否运行、延迟、状态文字、LED 质量）不再通过自定义事件广播，而是写入 PollingStore：

  • PollingStore 继承 ObservableObject，4 个 [ObservableProperty]
  • 任何关心轮询状态的 ViewModel 只需注入 Store，XAML 直接绑定
  • PollingScheduler 不再声明 PollingStarted/PollingStopped 事件，改为直接写 _store.IsRunning = true 等

PollingStore 属性一览

属性类型说明
IsRunningbool轮询是否运行中
LatencyMslong最新一次轮询延迟（毫秒）
StatusTextstring"轮询运行中" / "已停止" 等
QualityLedQualityLED 指示灯状态

报警规则的阈值比较使用 GetDoubleValue() 统一获取数值：

  • DbPollItem.DataType 声明 PLC 变量类型，决定读取字节数和解码方式
  • PollingScheduler 使用 _typedValues 字典存放解码后的 double，key 格式 DB{DbNumber}:{Offset}
  • AlarmService 通过 GetDoubleValue() 优先查 typed 值，没有再回退到 byte
DataType字节数解码方法
BYTE使用 Lengthbuf[0]
WORD / INT2S7.GetWordAt / S7.GetIntAt
DINT / REAL4S7.GetDIntAt / S7.GetRealAt
LREAL8BitConverter.ToDouble (大端)

持久化方案

报警历史存储路径：%APPDATA%\KesaPlc\alarms.json

规则存储路径：%APPDATA%\KesaPlc\rules.json

默认规则文件：{EXE 目录}\default-rules.json（应用自带，只读）

格式：JSON 数组，UTF-8 编码

规则加载策略：

  • 优先加载 %APPDATA%\KesaPlc\rules.json（用户编辑后的规则）
  • 若该文件不存在或为空，从应用自带的 default-rules.json 复制一份
  • 用户通过 UI 编辑规则后保存到 %APPDATA%，不会覆盖默认文件
  • 想重置为默认规则 → 删除 %APPDATA%\KesaPlc\rules.json 重启应用

报警历史策略：

  • 每次新报警产生时 追加保存（性能优化：防抖 2 秒写一次）
  • 最大保留 10000 条历史报警，超出时删除最早的
  • 启动时自动加载，关机时自动保存
  • 搁置状态、备注、确认信息一并持久化

数据类型 UI 集成

报警规则的编辑界面直接集成 DataType 下拉选择，实现「规则即配置」：

  • AlarmRule.DataType — 新增属性，默认 "BYTE"，与 DbPollItem.DataType 对齐
  • 绑定联动的 DbPollItem — 保存规则时若 VariableKey 为 DB{N}:{O} 格式，自动在 PollingScheduler 中创建对应的 DbPollItem
  • 无需手动配置 — 用户在 UI 中选好变量名和数据类型，PLC 轮询在下一周期自动生效

Deadband（死区）原理

常规触发 (抖动):
  值  ├───┬───┬───┬───┬───┬───┬───┲━━━┓
      │   │   │   │   │   │   │   ┃   ┃
 阈───┼───┼───┼───┼───┼───┼───┼───╂───╂───
      │   │   │   │   │   │   │   ┃   ┃
      └───┴───┴───┴───┴───┴───┴───┚   ┃
      报警╌╌╌╌╌╌╌╌╌╌╌╌┐  ┌╌╌╌╌╌╌╌╌╌╌╌  恢复
                      ↓  ↑
                      ON OFF ON OFF (抖动!)

带死区 (稳定):
  值  ───┬─────────────────────┐
         │                     │
 阈──────┼─────────────────────┼────
         │    死区 ↑           │
         │  ┌──────────┐       │
         │  │ 不回切    │       │
         └──┴──────────┴───────┘
      报警╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌   稳定恢复

  > 值超过阈值+死区 → 触发报警
  > 值降到阈值以下 → 不立即恢复，需降到阈值-死区才恢复
  > 死区宽度 = 阈值 × 死区百分比（默认 2%）

交互细节

  • 列排序 — 点击列头排序 (时间/级别/变量/状态/区域)，再次点击反向
  • 报警详情 — 点击行展开详情面板，显示完整信息
  • 闪烁效果 — 未确认的 Emergency/Critical 报警行使用 DoubleAnimation 背景闪烁
  • 搁置对话框 — 点击搁置弹出选择时长 (15min / 1h / 8h / 24h / 自定义)
  • 导出 CSV — 自动打开保存对话框，默认文件名含时间戳

八、持久化方案

💾 存储机制

  • 路径: %APPDATA%\KesaPlc\alarms.json
  • 序列化: System.Text.Json
  • 最大记录数: 10000 条
  • 写入策略: 防抖 2 秒批写入
  • 启动时: 自动加载到内存
  • 关机时: 自动保存

📤 导出机制

  • 格式: CSV UTF-8 with BOM
  • 列: 时间、严重度、类型、变量、描述、区域、值、阈值、状态、确认人、确认时间、备注
  • 保存对话框: 默认文件名 报警记录_2026-06-24.csv
  • 导出数据: 当前过滤后的可见行 (所见即所得)
