📈 趋势图时间窗口问题分析报告

症状

现象："1 分钟" 时间范围正常显示数据，但切换到 "5 分钟"、"30 分钟"、"1 小时"、"12 小时"、"24 小时" 后，趋势图上看不到数据或数据不更新。

根因分析：int 乘法溢出

问题代码位置：MainWindow.xaml.cs — UpdateTrendXAxis() 和 SlideTrendXAxis() 方法

关键表达式：

double n = DateTime.Now.Ticks;
cartesianTrend.XAxes = [MakeTrendAxis(n - _trendTimeWindowMs * 10_000, n)];

_trendTimeWindowMs 是 int 类型，10_000 也是 int 字面量。
在 C# 中 int * int 的结果仍然是 int（32 位有符号），最大值为 2,147,483,647。

时间范围_trendTimeWindowMs× 10_000溢出？实际 int32 结果
1 分钟60,000600,000,000✅ 否600,000,000
5 分钟300,0003,000,000,000💥 溢出-1,294,967,296
30 分钟1,800,00018,000,000,000💥 溢出820,130,816
1 小时3,600,00036,000,000,000💥 溢出1,640,261,632
12 小时43,200,000432,000,000,000💥 溢出-1,791,696,896
24 小时86,400,000864,000,000,000💥 溢出711,573,504
为什么 1 分钟能工作：60,000 × 10,000 = 600,000,000，小于 int.MaxValue(2,147,483,647)，不溢出。
为什么 5 分钟以上不工作：结果溢出变成负数或错误值，导致 X 轴 MinLimit > MaxLimit，LiveCharts2 无法渲染有效范围，数据全部不可见。

官网对比：LiveCharts2 2.0.4 的推荐做法

从 LiveCharts2 WPF 2.0.4 官方样例（samples.lines.basic / samples.axes）可以看到：

  • 官方实时图表的 X 轴总是用 TimeSpan.Ticks 或 DateTime.Now.Ticks 的 long 类型计算
  • 不会在每次数据更新时 新建 Axis 对象，而是复用已有的 Axis 实例
  • 数据源用 ObservableCollection<DateTimePoint>，这是正确的

次要问题

#问题影响
2 SlideTrendXAxis() 每次数据到达（100ms/次）都新建 Axis[] 数组 性能浪费，频繁触发 LiveCharts2 内部重布局。大窗口时 UI 线程负担重

修复方案

🔧 核心修复（必须）

修复 int 溢出：将乘法转为 long 计算

更改 1：UpdateTrendXAxis 和 SlideTrendXAxis

// ❌ 当前代码（int 溢出）
double n = DateTime.Now.Ticks;
cartesianTrend.XAxes = [MakeTrendAxis(n - _trendTimeWindowMs * 10_000, n)];

// ✅ 修复：用 TimeSpan 计算，避免手写乘法
private void UpdateTrendXAxis()
{
    var window = TimeSpan.FromMilliseconds(_trendTimeWindowMs);
    double now = DateTime.Now.Ticks;
    cartesianTrend.XAxes = [MakeTrendAxis(now - window.Ticks, now)];
}

private void SlideTrendXAxis()
{
    // 更好的做法：复用现有 Axis 对象，不新建数组
    var window = TimeSpan.FromMilliseconds(_trendTimeWindowMs);
    double now = DateTime.Now.Ticks;
    var axis = cartesianTrend.XAxes[0];
    axis.MinLimit = now - window.Ticks;
    axis.MaxLimit = now;
}

或者更简单的单行修复：

// ✅ 修复：将 _trendTimeWindowMs 转 long 再乘
double n = DateTime.Now.Ticks;
cartesianTrend.XAxes = [MakeTrendAxis(n - (long)_trendTimeWindowMs * 10_000, n)];

⚡ 性能优化（建议）

更改 2：不要在每次数据到达时重建 Axis

// ❌ 当前：每次 OnTrendSample 都新建 Axis[]
private void OnTrendSample(...)
{
    // ...
    SlideTrendXAxis(); // 每 100ms 执行一次
}

// ✅ 优化：只在切换时间范围时更新极限值
// CmbTrendTimeRange_Changed 中调用 UpdateTrendXAxis()
// OnTrendSample 中只 SlideTrendXAxis() — 复用 Axis 实例

private void SlideTrendXAxis()
{
    var window = TimeSpan.FromMilliseconds(_trendTimeWindowMs);
    double n = DateTime.Now.Ticks;
    var axis = cartesianTrend.XAxes[0];  // 复用，不 new
    axis.MinLimit = n - window.Ticks;
    axis.MaxLimit = n;
}

📅 标签格式化优化（建议）

更改 3：根据窗口大小自适应时间格式

// ✅ 优化：根据时间窗口选择不同的时间格式
private static Axis MakeTrendAxis(double min, double max, int timeWindowMs)
{
    string format = timeWindowMs switch
    {
        <= 300_000  => "HH:mm:ss",       // ≤5分钟：显示秒
        <= 3_600_000 => "HH:mm",         // ≤1小时：显示分
        <= 43_200_000 => "MM/dd HH:mm",  // ≤12小时：显示日期+时分
        _            => "MM/dd HH:mm",   // >12小时：显示日期+时分
    };

    return new Axis
    {
        MinLimit = min,
        MaxLimit = max,
        Labeler = v => new DateTime((long)v).ToLocalTime().ToString(format),
    };
}

调用处改为：MakeTrendAxis(n - window.Ticks, n, _trendTimeWindowMs)

📉 缓冲裁剪优化（建议）

更改 4：裁剪缓冲区时按时间窗口保留数据

// ✅ 优化：只保留当前时间窗口内的数据
private void TrimBuffer(ObservableCollection<DateTimePoint> buf)
{
    var cutoff = DateTime.Now - TimeSpan.FromMilliseconds(_trendTimeWindowMs * 2);
    while (buf.Count > 0 && buf[0].DateTime < cutoff)
        buf.RemoveAt(0);
}
