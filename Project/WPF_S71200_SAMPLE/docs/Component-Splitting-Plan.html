WPF 组件拆分方案

基于本项目现状 + 工业界标准 WPF 实践，不涉及 MVVM 框架迁移，只做 XAML + Code-Behind 的组件化拆分。

一、成熟的 WPF 项目是怎么拆的？

调研了四个方向的工业级 WPF 项目结构：

📐 模式 A：功能区域拆分（MahApps.Metro / MaterialDesignInXAML）
// 最主流的拆分方式 — 按 UI 区域切 UserControl Shell/ ├── MainWindow.xaml // 仅骨架：Grid + 区域占位 ├── MainWindow.xaml.cs // 仅窗口级事件（关闭、主题） Controls/ ├── Sidebar/ │ ├── ConnectionPanel.xaml // 连接参数 + 按钮 │ ├── ImportPanel.xaml // 导入 DB/UDT │ └── PollingPanel.xaml // 轮询配置 ├── IoPanel/ │ ├── IAreaPanel.xaml // I 区（只读） │ ├── QAreaPanel.xaml // Q 区（可读写） │ └── MAreaPanel.xaml // M 区（可读写） ├── Trend/ │ ├── TrendChartPanel.xaml // 趋势图 │ ├── GaugeControl.xaml // 水平轴仪表 │ └── BarChartPanel.xaml // 柱状图 └── Common/ ├── BitBlock.xaml // 可复用的位块组件 └── ByteRow.xaml // 可复用的字节行组件

特点：每个 UserControl 就是一个独立 xaml + cs，事件在自己内部处理，通过 DependencyProperty / 事件暴露给父级。一般大型项目都这样拆。

📐 模式 B：MVVM 分层（Prism / CommunityToolkit.Mvvm）
// 企业级标准 — View + ViewModel 一一对应 Views/ ├── SidebarView.xaml ├── IAreaView.xaml ├── QAreaView.xaml ├── MAreaView.xaml ├── TrendView.xaml └── GaugeView.xaml ViewModels/ ├── SidebarViewModel.cs ├── IAreaViewModel.cs ├── QAreaViewModel.cs ├── MAreaViewModel.cs ├── TrendViewModel.cs └── GaugeViewModel.cs

特点：Code-Behind 几乎为空，所有逻辑在 ViewModel 里用 Binding 驱动。适合大型团队协作。

📐 模式 C：按 Tab / 页面拆分（最轻量，适合你）
// 你当前已经是 Tab 布局了，只是内容全写在一个文件里 // 最小改动：把每个 Tab 内容拆成独立 UserControl，主窗只做引用 MainWindow.xaml ← 只留 Shell 骨架 ├── Sidebar.xaml ← 侧边栏全部移过去 ├── IoPanel.xaml ← Tab1: I/Q/M 读写面板 ├── TrendPanel.xaml ← Tab2: 趋势图面板 └── GaugePanel.xaml ← Tab3: 仪表盘面板

特点：介于 A 和 B 之间，不引入第三方框架，每个 Tab 对应一个 UserControl，事件通过 EventArgs 冒泡或通过共享的 Service 通信。

文件行数问题

Styles.xaml可以全局样式集中管理，这个是好的，保留。
Themes/Dark.xaml + Light.xaml可以主题资源字典，好的，保留。

三、推荐方案：模式 C — 按 Tab 区域拆分 + 公共控件下沉

拆分原则
  1. 一个 Tab 一个 UserControl — I/Q/M 面板、趋势面板、仪表盘各一个文件
  2. 侧边栏独立 — 连接配置 + 导入 + 轮询是一个独立模块
  3. 公共控件下沉 — BitBlock、ByteRow 这些被多处引用的做成可复用 UserControl
  4. 不引入第三方框架 — 纯 UserControl + DependencyProperty + 事件，保持简单
  5. 事件冒泡 — 子组件触发事件，父级（MainWindow）监听并调用 Service

目标目录结构

方向方式例子
子 → 父事件冒泡（new RoutedEvent 或 EventHandler）BitBlock 被点击 → BitToggled 事件 → QPanel 调用 S7Service.WriteByte()
父 → 子DependencyProperty 绑定PollingPanel.LatencyMs → MainWindow 轮询回调时设值

五、建议的拆分顺序（6 步，可分批做）

🟢 第 1 步：把 Common 控件抽出来

先把 BitBlock 和 ByteRow 从 I/Q/M 三处内联 DataTemplate 提成独立 UserControl。

  • Controls/Common/BitBlock.xaml ← 目前 I/Q/M 三处重复定义了同样的 Bit Border 模板
  • Controls/Common/ByteRow.xaml ← 行模板也只定义一次
  • 好处：改位块样式只用改一个文件，三区同步
🟢 第 2 步：拆分侧边栏

侧边栏内部有 3 个逻辑块，但内部耦合不高，可以拆成 3 个独立面板，也可以先合成一个 SidebarControl：

  • ConnectionPanel：网卡/IP/端口/机架/槽位 + 连接/断开按钮 + 状态指示
  • ImportPanel：导入 DB/UDT + 已导入列表
  • PollingPanel：间隔输入 + 启停按钮 + 延迟显示 + 状态

建议：先合为 SidebarControl，后续再进一步拆。

🟢 第 3 步：拆分 I 区

I 区是纯只读，和 Q/M 的行为不同（无写入、无写模式切换）。直接搬成 IAreaPanel。

🟢 第 4 步：拆分 Q 区和 M 区

Q 和 M 结构几乎一样（标题/标签色不同 + 写入模式切换 + "已修改"状态列），可以共用一个 AreaPanelBase，传入不同参数区分：

// Q 和 M 都基于 AreaPanelBase <controls:AreaPanelBase AreaType="Q" Color="Green"/> <controls:AreaPanelBase AreaType="M" Color="Purple"/>
🟢 第 5 步：拆分趋势图 Tab

趋势面板包含：通道列表 + 时间范围 ComboBox + LiveCharts 趋势图 + 水平仪表 + 柱状图。拆成 3 个：

  • TrendChartPanel — 通道列表 + 趋势图（核心）
  • HorizontalGauge — 水平轴伺服仪表
  • BarChartPanel — 柱状图
🟢 第 6 步：拆分仪表盘 Tab

两个 AngularGauge + 各自的配置面板，拆成两个独立 UserControl：

  • AngularGaugeSingle — 单值速度表 + 配置面板
  • AngularGaugeMulti — 多区段仪表 + 区段列表

七、注意事项

⚡ 重要提醒
  1. 别引入第三方 MVVM 框架 — Prism / CommunityToolkit.Mvvm 学习成本高，纯 UserControl + 依赖注入（构造传参）足够当前场景。
  2. S7Service 保持单例 — 所有组件共享同一个 S7Service 和 PollingScheduler 实例，通过 MainWindow 构造后传参给子组件。
  3. I 区特殊 — I 区是只读的，没有写模式切换，所以它不和 Q/M 共用 AreaPanelBase。Q/M 可以共用。
  4. 事件不绑到 Window 上 — 像 BitBlock_MouseDown 这种事件要移到对应的 UserControl 里去处理，不会跑到 MainWindow 的 code-behind 里。
  5. Resources 合并 — Styles.xaml 和 Themes/ 放在 App.xaml 的 MergedDictionaries 里全局生效，子组件不需要再引用。
