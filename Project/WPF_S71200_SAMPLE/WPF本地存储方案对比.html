💾 WPF / .NET 本地存储方案对比

对标 Web localStorage · 选型指南 · 2026-06
📊 四方案速览
方案 对标 Web 存储位置 格式 大小限制 复杂度
Properties.Settings 📦 localStorage user.config XML ~500KB 极低
JSON 文件 📄 IndexedDB 你指定路径 JSON 无（磁盘满为止） 低
IsolatedStorage 🗑️ Web SQL (已废弃) 沙箱目录 二进制/XML ~几 MB 中
SQLite 🗃️ IndexedDB 你指定 .db 文件 SQL 关系型 无（TB 级） 中

📦 方案一：Properties.Settings 对标 localStorage

内置键值存储 —— 最简单，但有坑
使用方式项目属性 → 设置 → 声明字段 → 代码读写
存储路径C:\Users\你\AppData\Local\项目名\版本号\user.config
数据格式XML 明文（记事本可打开）
读写代码Settings.Default.xxx = value; Settings.Default.Save();
✅ 适合
IP 地址 · 端口 · 机架/槽位 · 窗口位置 · 主题选择 · 是否记住密码
❌ 不适合
DB 列表（List无法直存）· 大数据（>1MB）· 动态 key · 多线程高频写
// 先在项目属性 → 设置 声明：
// LastConnectedIP (string) = ""
// ThemeMode (string) = "Dark"
// WindowTop (int) = 100

// 写入
Properties.Settings.Default.LastConnectedIP = txtIP.Text;
Properties.Settings.Default.ThemeMode = "Light";
Properties.Settings.Default.Save();

// 读取
txtIP.Text = Properties.Settings.Default.LastConnectedIP;
bool isDark = Properties.Settings.Default.ThemeMode == "Dark";

📄 方案二：JSON 文件 对标 localStorage + 自定义

自己读写 JSON 文件 —— 灵活、可控、足够
使用方式JsonSerializer + File.Read/WriteAllText
存储路径AppDomain.CurrentDomain.BaseDirectory + "config.json"（你决定）
数据格式JSON 明文（可读、可编辑、可版本控制）
读写代码两行：序列化 → 写文件 / 读文件 → 反序列化
✅ 适合
DB 轮询列表 · I/Q/M 地址范围 · 轮询配置 · 任意复杂结构 · 你项目中大部分数据
❌ 不适合
高频写入（每 50ms 写一次会坏文件）· 大量结构化查询（>几万行）· 多线程并发写
// 定义你的配置模型
public record AppConfig
{
  public string LastIP { get; set; } = "";
  public bool IsDark { get; set; } = true;
  public List<DbPollItem> DbItems { get; set; } = [];
}

// 写入（startup / 每次配置变化时保存）
var cfg = new AppConfig { LastIP = txtIP.Text, IsDark = isDark, DbItems = ... };
File.WriteAllText("app_config.json", JsonSerializer.Serialize(cfg, new JsonSerializerOptions { WriteIndented = true }));

// 读取
if (File.Exists("app_config.json"))
  cfg = JsonSerializer.Deserialize<AppConfig>(File.ReadAllText("app_config.json"));
你的 DbPollItem 列表 → JsonSerializer → app_config.json （可读、可手工编辑、可备份）

🗑️ 方案三：IsolatedStorage 不推荐

过时的沙箱存储 —— .NET 早期方案，已被淘汰
使用方式IsolatedStorageFile.GetStore()
存储路径深层系统沙箱目录，用户找不到
数据格式二进制或 XML（你控制）
现状微软已不再推荐，.NET 10 仍保留但无新特性
为什么不用
① API 繁琐（要开流、写字节）
② 文件藏在系统沙箱里，调试想删都找不到
③ JSON 文件两行代码能做到的事，它能写十几行
④ 跨版本升级会丢数据（跟 Settings 一样）

🗃️ 方案四：SQLite 对标 IndexedDB

轻量嵌入式数据库 —— 本地存储的"重武器"
使用方式Microsoft.Data.Sqlite NuGet 包
存储位置一个 .db 文件，你指定路径
数据格式SQL 关系型表
大小限制无（TB 级）
依赖需安装 NuGet 包（本项目中已装了）
✅ 适合
大量结构化数据（历史记录、日志）· 需要 SQL 查询 · 多表关联 · >10MB 数据
❌ 大炮打蚊子
存几个 DB 配置和 IP 地址 · 杀鸡用牛刀
// NuGet（项目中已装）
Install-Package Microsoft.Data.Sqlite

// 建表 + 写入
using var conn = new SqliteConnection("Data Source=plc_data.db");
conn.Open();
var cmd = conn.CreateCommand();
cmd.CommandText = "CREATE TABLE IF NOT EXISTS history (time TEXT, value REAL)";
cmd.ExecuteNonQuery();

cmd.CommandText = "INSERT INTO history VALUES(@t, @v)";
cmd.Parameters.AddWithValue("@t", DateTime.Now.ToString());
cmd.Parameters.AddWithValue("@v", 42.5);
cmd.ExecuteNonQuery();

💡 对你项目的建议

🔹 Settings 存元数据 + JSON 文件存配置

Settings 存（多少无所谓，简单键值）：

LastConnectedIP · WindowLeft/WindowTop · ThemeMode

JSON 文件存（复杂结构）：

app_config.json ← DB 轮询列表 + I/Q/M 地址范围 + 轮询启停状态

需要改代码吗？不用 —— 你已有的 DbPollItem 模型直接就能序列化成 JSON。

两个方案加起来代码不超过 20 行，零依赖。

🔀 决策树 —— 按需选择

数据是简单键值对（IP、主题、位置）？
── ✅ Settings  （一行代码）
数据是复杂对象（DB列表、配置表）？
── ✅ JSON 文件  （JsonSerializer 两行代码）
数据量 > 10MB 或需要查询历史？
── ✅ SQLite  （项目已装 Sqlite 包）
你想用几十年前过时的 API？
── ❌ IsolatedStorage  （别）
