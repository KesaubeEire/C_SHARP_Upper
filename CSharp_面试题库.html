Q1int 在 C# 里多少位？PLC 里多少位？

C#：int = 32 位（-21 亿 ~ 21 亿）

PLC（博途/STEP 7）：INT = 16 位（-32768 ~ 32767），DINT = 32 位

原因：PLC 的 INT 是 IEC 61131-3 标准规定的 16 位历史产物；C# 的 int 是跟 CPU 字长对齐的 32 位设计选择。上位机开发时要手动做类型映射。

C# 接 PLC 数据：
    ushort rawValue = register.Value;      // PLC WORD → C# ushort（16位）
    short signed = (short)rawValue;         // PLC INT → C# short（16位）
    int dint = (regHigh << 16) | regLow;   // PLC DINT → C# int（32位）
    double actual = rawValue * 0.1;         // 计算时转 double 防溢出
Q2字段（field）和属性（property）有什么区别？

字段 = 变量，直接存数据，裸奔

属性 = 带 get/set 门卫的字段，可以在访问时加逻辑

// 字段 — 直接公开，没有任何保护
public int age;

// 属性 — get/set 可以加校验、触发事件、计算
private int _age;
public int Age
{
    get => _age;
    set
    {
        if (value < 0 || value > 150)
            throw new ArgumentException("年龄不合法");
        _age = value;
    }
}

// 自动属性（C# 3.0+） — 编译器生成隐藏字段
public string Name { get; set; }

设计原则：字段永远 private，对外暴露用属性。纯数据用自动属性 { get; set; }，需要逻辑时改成完整属性。

Q4装箱和拆箱是什么？

装箱：值类型 → object 引用类型（栈→堆）

拆箱：object 引用类型 → 值类型（堆→栈）

int value = (int)obj;      // 拆箱：堆上的 object 转回 int

Q5StringBuilder 和 string 拼接的区别？

string 是不可变的！每次 += 都会创建一个新字符串，旧的等着 GC 回收。

// ❌ 低效：每次循环都创建新字符串
string s = "";
for (int i = 0; i < 1000; i++)
    s += i + ",";  // 创建了 1000 个临时字符串

// ✅ 高效：StringBuilder 内部用可变缓冲区
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++)
    sb.Append(i).Append(",");
string result = sb.ToString();

什么时候用 StringBuilder：循环拼接、大量拼接、不知道最终长度的拼接。

什么时候直接用 +：拼接次数固定且很少（3-5 次），编译器会优化成 string.Concat。

Q12什么是委托？

委托 = 方法的"指针"，可以把方法当作参数传递

// 定义一个委托类型

// 符合委托签名的方法

void WriteToConsole(string msg) => Console.WriteLine(msg);

// 使用

logger = WriteToConsole;          // 切换实现
logger("这行打印到控制台");

// 多播委托：一个委托指向多个方法
logger += WriteToFile;
logger("两处都会记录");

// 框架预定义的委托
Func predicate;    // 有返回值，最后一个是返回类型
Action action;        // 无返回值

Q14?? 和 || 在 C# 里和 JS/TS 里有什么区别？

核心区别：

表达式C#JS/TS原因
0 || 1❌ 编译错误✅ 返回 1C# 只看 bool，JS 看 truthy
"" || "默认"❌ 编译错误✅ 返回 "默认"同上
null || "默认"❌ 编译错误✅ 返回 "默认"C# 不认 null 为 bool
null ?? "默认"✅ 返回 "默认"✅ 返回 "默认"一致，只认 null
0 ?? 100✅ 返回 0✅ 返回 0一致，不认 falsy
// C#：|| 只用于 bool，?? 只认 null
bool result = true || false;     // OK
int num = GetValue() ?? 100;     // 如果返回 null 则用 100

// JS：|| 返回第一个真值（会吃掉 0 和 ""）
let count = input || 10;         // 如果 input=0，会变成 10（bug！）
let safe = input ?? 10;          // 只有 null/undefined 才替换（正确）

面试结论：C# 类型严格，不容易踩坑；JS 的 || 把 0 和 "" 当 falsy 吃掉，推荐用 ?? 代替。

Q21怎么防止跨线程操作 UI 控件？

WinForms 规则：只能在 UI 线程上操作控件。串口/网络回调在后台线程。

// 你的项目代码：SafeInvoke
private void SafeInvoke(Action action)
{
    if (_disposed) return;
    if (_uiControl.IsDisposed) return;

    if (_uiControl.InvokeRequired)
        _uiControl.Invoke(action);   // 封送到 UI 线程
    else
        action();                    // 已经在 UI 线程
}

// 另一种写法（C# 3.0+）
box_recv.InvokeIfRequired(() =>
{
    box_recv.AppendText("收到数据\r\n");
});

// 扩展方法（你项目里可以这样写）
public static void InvokeIfRequired(this Control control, Action action)
{
    if (control.InvokeRequired)
        control.Invoke(action);
    else
        action();
}

Q25SerialPort 的 DataReceived 事件在哪个线程？要注意什么？

在后台线程触发！三件事必须注意：

① 不能直接操作 UI — 要用 Invoke 封送

② 一次事件可能没收到完整数据 — 要 Sleep(50) 等待

③ 必须实现 IDisposable — 程序崩溃后串口可能被锁死

private void Sp_DataReceived(object sender, SerialDataReceivedEventArgs e)
{
    Thread.Sleep(50);  // 等数据收完
    int count = _sp.BytesToRead;
    if (count <= 0) return;

    byte[] buf = new byte[count];
    _sp.Read(buf, 0, count);
    SafeInvoke(() => FrameReceived?.Invoke(buf, false));
}

public static string Decrypt(byte[] cipherBytes)
{
    byte[] plainBytes = ProtectedData.Unprotect(cipherBytes, null,
        DataProtectionScope.CurrentUser);
    return Encoding.UTF8.GetString(plainBytes);
}

优点：零配置，密钥由操作系统派生和管理，代码改动极小。

注意：同一台机器同一用户才能解密，重装系统后数据作废。

方案三：Token + Refresh Token（最主流、最安全）

// 第一次登录
POST /api/login  { username, password }
← 返回 { access_token: "eyJ...", refresh_token: "xxx", expires_in: 3600 }

// 客户端只存 refresh_token（用 DPAPI 加密存文件）
// access_token 内存中持有，程序关闭即消失

// access_token 过期
POST /api/refresh  { refresh_token: "xxx" }
← 返回新的 { access_token: "eyJ...", expires_in: 3600 }
// 密码只在登录那一刻用过，后面全是 token

优点：密码不进客户端，refresh_token 有效期短且可撤销，服务器可踢人下线。

方案四：OAuth 2.0 + 系统 Web 登录（SSO）

客户端弹出系统浏览器 → 用户在认证页输入密码 → 授权码回传到客户端 → 换 token。客户端完全接触不到密码。

典型场景："使用 Microsoft 账号登录"、"使用微信扫码登录"。

面试回答要点：

"WinForms 客户端保存凭据，最稳妥的方案是 Windows Credential Manager + Refresh Token。密码只在首次登录时使用，后续用 token 认证。token 需要持久化时，存入凭据管理器而非文件。DPAPI 是纯 .NET 项目的最简替代方案，加密粒度限于当前 Windows 用户。明文存密码在任何生产环境都属于安全漏洞，不能上线。"
