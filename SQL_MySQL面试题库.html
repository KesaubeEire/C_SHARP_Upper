Q2什么是主键？什么是外键？

主键（Primary Key）：表中唯一标识每一行的字段，不能重复，不能为 NULL

id BIGINT PRIMARY KEY IDENTITY(1,1)  -- SQL Server 自增主键

外键（Foreign Key）：一个表中引用另一个表主键的字段，用于建立表之间的关联

FOREIGN KEY (user_id) REFERENCES users(id)  -- 订单表引用用户表
Q3CHAR 和 VARCHAR 的区别？
CHAR(10)VARCHAR(10)
长度固定 10 字符可变，最长 10 字符
存 "abc"占 10 字节占 4 字节（3+1）
速度快（固定长度好计算）稍慢（需要记录长度）
适用设备 ID（固定长度）备注、名称（可变长度）
Q4什么是事务？什么是 ACID？

事务 = 一组操作，要么全部成功，要么全部失败

特性含义例子
A 原子性要么全做，要么全不做写3个寄存器，1个失败全部回滚
C 一致性事务前后数据状态一致转账前后总金额不变
I 隔离性多个事务互不干扰两个上位机同时写不会冲突
D 持久性提交后数据永久保存断电重启数据还在
Q5什么是索引？什么时候建索引？

索引就像书的目录，让数据库不用全表扫描就能找到数据

应该建索引：

① WHERE 后面经常出现的字段（device_id, timestamp）

② ORDER BY 后面的字段

③ JOIN 连接用的字段

不应该建索引：

① 数据量很小的表

② 经常写入很少查询的表（索引会拖慢写入）

③ 区分度低的字段（如"性别"只有男/女）

上位机场景：timestamp 和 device_id 应该建索引，因为查询经常按时间和设备筛选

Q6写一个建表语句

SQL Server 写法：

CREATE TABLE production_data (
    id           BIGINT PRIMARY KEY IDENTITY(1,1),
    timestamp    DATETIME NOT NULL,
    device_id    NVARCHAR(50) NOT NULL,
    address      INT NOT NULL,
    raw_value    INT NOT NULL,
    actual_value FLOAT,
    name         NVARCHAR(100)
);

-- 建索引
CREATE INDEX idx_timestamp ON production_data(timestamp);
CREATE INDEX idx_device ON production_data(device_id);

MySQL 区别：IDENTITY(1,1) → AUTO_INCREMENT，NVARCHAR → VARCHAR，FLOAT → DOUBLE

Q7增删改查各写一条

增 INSERT：

INSERT INTO production_data (timestamp, device_id, address, raw_value, actual_value)
VALUES (GETDATE(), 'PLC-1', 100, 1200, 120.0);

删 DELETE — 删除 30 天前的数据：

-- SQL Server
DELETE FROM production_data
WHERE timestamp < DATEADD(DAY, -30, GETDATE());

-- MySQL
DELETE FROM production_data
WHERE timestamp < DATE_SUB(NOW(), INTERVAL 30 DAY);

改 UPDATE — 确认报警：

UPDATE alarm_history
SET status = '已确认', confirmed_at = GETDATE(), confirmed_by = '操作员'
WHERE id = 42;

查 SELECT — 按设备统计最近 1 小时数据量：

SELECT device_id, COUNT(*) AS cnt
FROM production_data
WHERE timestamp >= DATEADD(HOUR, -1, GETDATE())  -- SQL Server
-- WHERE timestamp >= DATE_SUB(NOW(), INTERVAL 1 HOUR)  -- MySQL
GROUP BY device_id
ORDER BY cnt DESC;
Q8什么是参数化查询？为什么要用？

❌ 错误：字符串拼接（有 SQL 注入风险）

string sql = "SELECT * FROM users WHERE name = '" + userName + "'";
-- 如果 userName = "' OR 1=1 --"，就能查出所有数据

✅ 正确：参数化查询

string sql = "SELECT * FROM users WHERE name = @name";
cmd.Parameters.AddWithValue("@name", userName);

用参数化查询的三个原因：

① 防止 SQL 注入攻击

② 数据库可以缓存执行计划，重复查询更快

③ 不用手动处理特殊字符（单引号等）

Q9GROUP BY 和 HAVING 的区别？
-- GROUP BY：分组
SELECT device_id, COUNT(*) AS cnt
FROM alarm_history
GROUP BY device_id;

-- HAVING：对分组结果过滤
SELECT device_id, COUNT(*) AS cnt
FROM alarm_history
GROUP BY device_id
HAVING COUNT(*) > 10;  -- 只看报警超过 10 次的设备

WHERE → 分组前过滤（过滤原始行）
HAVING → 分组后过滤（过滤分组结果，可用于聚合函数）

Q10LEFT JOIN 和 INNER JOIN 的区别？
-- INNER JOIN：只返回两表都匹配的行（交集）
SELECT o.*, u.name
FROM orders o INNER JOIN users u ON o.user_id = u.id;
-- 用户被删了 → 订单也查不出来

-- LEFT JOIN：左表全要 + 右表能匹配就匹配
SELECT o.*, u.name
FROM orders o LEFT JOIN users u ON o.user_id = u.id;
-- 用户被删了 → 订单也能查出来，name 显示 NULL
类型含义记忆口诀
INNER JOIN交集（只要匹配的）"两表都有才要"
LEFT JOIN左表全要 + 右表匹配"左边为主，右边凑"
RIGHT JOIN右表全要 + 左表匹配"右边为主，左边凑"
FULL JOIN并集（两边都要）"全都要"

Q11上位机高频采集数据，怎么存？

不能每条数据都直接写数据库（太频繁，数据库扛不住）

方案：内存缓冲 + 批量写入

① 用 ConcurrentQueue 先把数据存内存

② 攒够 100 条或每 5 秒批量写入一次

③ 用 SqlBulkCopy（SQL Server）批量插入

④ 定期清理 30 天前的历史数据

private readonly ConcurrentQueue<DataPoint> _buffer = new();

public void OnData(DataPoint dp)
{
    _buffer.Enqueue(dp);
    if (_buffer.Count >= 100) FlushToDb();
}

private void FlushToDb()
{
    var batch = new List<DataPoint>();
    while (_buffer.TryDequeue(out var r))
        batch.Add(r);
    BulkInsert(batch);  // 比逐条插入快 10-100 倍
}

Q13怎么防止数据库连接泄漏？

① 用 using 语句自动释放连接：

using (var conn = new SqlConnection(connStr))
{
    conn.Open();
    // 操作
}  // 自动调用 Dispose，释放连接

② 连接池：ADO.NET 默认启用连接池，用完的连接不会真的关闭，放回池里复用

③ 不要在循环里反复 Open/Close，应该复用同一个连接

④ 异常时也要关闭：using 会自动处理，try/finally 也行

Q14什么是 SQL 注入？举个例子

SQL 注入 = 攻击者通过输入框注入恶意 SQL 语句，操纵数据库

登录验证例子：

原始 SQL: "SELECT * FROM users WHERE name='" + input + "' AND pwd='" + pwd + "'"

正常输入: name="admin", pwd="123"
→ SELECT * FROM users WHERE name='admin' AND pwd='123'  ✅

攻击输入: name="' OR 1=1 --", pwd="随便"
→ SELECT * FROM users WHERE name='' OR 1=1 --' AND pwd='随便'
→ OR 1=1 永远真，-- 注释掉后面  ❌ 绕过密码验证

防御：参数化查询，永远不要拼接 SQL

Q15怎么优化慢查询？

① 建索引：WHERE / ORDER BY / GROUP BY 涉及的字段

② 避免 SELECT *：只查需要的字段

③ 避免在 WHERE 里对字段做函数：

-- ❌ 慢：WHERE YEAR(timestamp) = 2026
-- ✅ 快：WHERE timestamp >= '2026-01-01' AND timestamp < '2027-01-01'

④ 分页查询：不要一次查几万条，用 LIMIT / TOP 分页

⑤ 批量操作：用 SqlBulkCopy 代替逐条 INSERT

⑥ 查看执行计划：SSMS 里按 Ctrl+L 看 SQL 怎么执行的

面试加分："我项目里 timestamp 和 device_id 建了索引，查询最近 1 小时某设备的数据从 2 秒优化到 0.01 秒。"

第四部分：高级题 加分

Q16存储过程是什么？

存储过程 = 存在数据库里的预编译 SQL 函数，可以有参数、有逻辑

CREATE PROCEDURE GetAlarmSummary
    @startDate DATETIME,
    @endDate DATETIME
AS
BEGIN
    SELECT level, COUNT(*) AS cnt
    FROM alarm_history
    WHERE timestamp BETWEEN @startDate AND @endDate
    GROUP BY level;
END;

-- 调用
EXEC GetAlarmSummary '2026-01-01', '2026-12-31';

优点：预编译执行更快、减少网络传输、集中管理业务逻辑
缺点：调试困难、移植性差（SQL Server 和 MySQL 语法不同）

Q17什么是死锁？怎么避免？

死锁 = 两个事务互相等待对方释放资源，谁也执行不了

事务A：锁了表1 → 想锁表2
事务B：锁了表2 → 想锁表1
→ 互相等待 → 死锁 → 数据库自动回滚其中一个

避免方法：

① 按固定顺序访问表（都先锁表1再锁表2）

② 减少事务时间（事务里不要做耗时操作）

③ 使用较低的隔离级别（READ COMMITTED）

④ 设置锁超时（SET LOCK_TIMEOUT 5000）

Q18数据库备份怎么做？
-- SQL Server 备份
BACKUP DATABASE MonitorDB TO DISK = 'D:\backup\MonitorDB.bak';

-- MySQL 备份
mysqldump -u root -p MonitorDB > backup.sql;

上位机场景：

① 每天凌晨自动备份一次

② 保留最近 7 天的备份

③ 备份文件压缩存储

④ 定期验证备份能恢复（备份不验证等于没备）

🎤 问：你项目里的数据库是怎么用的？

"我的上位机项目用 SQLite 做本地数据存储，设计了 Repository 模式封装 CRUD 操作，支持 SQLite 和 SQL Server 双模式切换。高频采集数据先缓存在 ConcurrentQueue 里，攒够批量写入减少数据库压力。timestamp 和 device_id 建了索引优化查询。定期清理 30 天前的历史数据防止数据库膨胀。报警记录、配方参数、生产统计都存在数据库里。"

🎤 问：SQL Server 和 MySQL 怎么选？

"新项目我选 SQL Server，因为跟 .NET 生态集成好，企业级功能强。如果是跨平台需求或者 Web 项目，选 MySQL，开源免费。SQLite 适合单机上位机，零配置，但并发写入弱。我的项目做了数据库抽象层，三种都能支持。"

🎤 问：数据量大了怎么办？

"我做了三层优化：① 批量写入，用 ConcurrentQueue 缓存 + SqlBulkCopy 批量插入，减少数据库压力；② 建索引，timestamp 和 device_id 字段建索引加速查询；③ 定期归档，30 天前的数据自动清理或移到历史表。如果数据量再大，可以按月分表。"
