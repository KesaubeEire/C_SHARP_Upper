A AI Agent 驱动开发全景

2025–2026 年，WPF / WinForms / C# /.NET 的开发范式正在被 AI Agent 重塑。核心变化：

  • AI 不再是"自动补全"工具，而是自主 Agent——能读代码库、跨文件编辑、运行测试、构建、调试
  • 开发者角色从"写代码的人"转变为架构师 + 审查者 + 提示工程师
  • 开发节奏从"线性的写→编→测"转变为并行的 Agent 协作 + 人工审查

CLAUDE.md 模板

# VS_Dev 项目规范

## 技术栈
- 框架: .NET 10.0-windows (WinForms / WPF)
- 语言: C# 12+（Nullable + ImplicitUsings）
- 协议: Modbus RTU/TCP
- UI: WPF (HandyControl / MahApps / MaterialDesign)

## 架构
- 分层: UI → ViewModel → Service → Transport/Protocol
- MVVM: CommunityToolkit.Mvvm（源生成器）
- DI: Microsoft.Extensions.DependencyInjection
- 日志: Serilog

## 代码规范
- 4 空格缩进, nullable 启用, 文件级命名空间
- 所有 ViewModel 必须是 partial class
- 异步必传 CancellationToken, 禁止 .Result / .Wait()
- 测试: xUnit + NSubstitute, AAA 模式

## 工具规则
- 编辑 .cs → 自动 format + build
- 添加 NuGet 包前先问我
- git commit/push 必须先审查
- 禁止修改 .Designer.cs（除非明确要求）

---
description: Write xUnit tests for a .NET class.
---
## Instructions
1. Read the target file to understand the class and its dependencies.
2. Read AGENTS.md for the project's test naming conventions.
3. Write tests using xUnit, NSubstitute, FluentAssertions.
4. Follow: `{MethodName}_{Scenario}_{ExpectedResult}` naming.
5. Cover: happy path, validation failures, edge cases, async cancellation.
6. Run `dotnet test` on the test project and fix any failures.

Agents：专用 Sub-agent

.claude/agents/code-reviewer.md

---
name: code-reviewer
description: Reviews .NET code changes for correctness and conventions.
model: claude-sonnet-4-7
tools: [Read, Bash]
---
You are a senior .NET developer. Before any review comment:
1. Run `dotnet build --no-restore` and read the output.
2. Run `dotnet test --no-restore` and read the output.
3. Only raise issues the build & test didn't catch if high confidence.

When reviewing, check for:
- DateTime.Now (use TimeProvider), Thread.Sleep (use await Task.Delay)
- HttpClient outside IHttpClientFactory
- Missing CancellationToken on async methods
- EF Core N+1 query pattern
Influence vs. Enforcement（影响 vs 强制）
• CLAUDE.md / Skills / Agents → 影响（Agent 通常遵守）
• Hooks / permissions.deny / 编译分析器（TreatWarningsAsErrors）→ 强制（Agent 无法绕过）
• 危险操作放强制，其余放影响

8 Roslyn 代码分析与质量门禁

AI 生成的代码必须经过自动化质量门禁。以下配置强制所有代码达到同一标准：

分析器用途配置
Microsoft.CodeAnalysis.NetAnalyzers内置 .NET 平台分析器AnalysisMode=All
Meziantou.Analyzer v3.x190+ 规则：安全/性能/设计/命名PackageReference，最新 3.0.98
SonarAnalyzer.CSharp代码异味、认知复杂度、Bug 模式PackageReference
Security Code Scan硬编码密钥、弱加密、危险 APINuGet + CI

Directory.Build.props（严格模式）

<Project>
  <PropertyGroup>
    <Nullable>enable</Nullable>
    <AnalysisLevel>latest</AnalysisLevel>
    <AnalysisMode>All</AnalysisMode>
    <EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
    <CodeAnalysisTreatWarningsAsErrors>true</CodeAnalysisTreatWarningsAsErrors>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Meziantou.Analyzer" Version="3.*">
      <PrivateAssets>all</PrivateAssets>
      <IncludeAssets>runtime; build; native; contentfiles; analyzers</IncludeAssets>
    </PackageReference>
    <PackageReference Include="SonarAnalyzer.CSharp" Version="9.*">
      <PrivateAssets>all</PrivateAssets>
      <IncludeAssets>runtime; build; native; contentfiles; analyzers</IncludeAssets>
    </PackageReference>
  </ItemGroup>
</Project>
效果：风格/命名/格式违规 = 硬编译错误。dotnet format 可自动修复。
Agent 第一个 dotnet build 就是质量门禁，无需人工介入格式审查。

7 关键结论

  1. WPF 没有死 — 金融、医疗、工控领域仍然是首选桌面技术
  2. MVVM 三选一：小项目 CommunityToolkit.Mvvm，大项目 Prism，实时加 ReactiveUI
