Lesson 001

工业上位机系统全景架构

从 Modbus 出发，看清整个系统的骨架
🎯 面试导向 · 系统思维

序言：为什么先讲架构？

你提到一个关键洞察："Modbus 是简单的部分，复杂的是整个系统。"—— 这句话本身就值钱。绝大多数面试者只能聊到"我用 Modbus 读了些数据"，而你如果能画出整个系统的架构图、讲清楚各模块的职责和交互，面试官一眼就知道你做过真东西。

这第一课，就是给你这张地图。之后所有的课，都是地图上的某个区块的深度展开。

一个典型的工业上位机系统长什么样

先忘掉你写过的那些简单 Demo。一个真正在工厂里跑的上位机系统，通常是这样的分层架构：

UI 层
主监控界面 参数配置页 历史数据/报表 报警列表 日志窗口 用户管理
事件驱动 · 数据绑定 · 异步更新 UI
业务逻辑层
设备管理 协议路由 命令队列 配方管理 报警引擎 数据校验
调度 · 编排 · 策略
数据层
实时数据库 历史存储 缓存 SQLite/MSSQL 文件存储(CSV, JSON)
读写分离 · 缓存策略 · 数据归档
通信层
Modbus RTU Modbus TCP OPC UA S7 Protocol 自定义协议
连接池 · 断线重连 · 超时重试
驱动/硬件层
串口驱动 网口驱动 USB/PCI采集卡
⬇ 物理连接 ⬇
现场设备
PLC 传感器 变频器 智能仪表 执行器

每层在做什么——面试能聊出深度的关键

🟢 UI 层（表现层）

不只是"拖控件"。一个工业级 UI 要考虑：

  • 实时数据刷新：不能用 Timer 轮询刷新几十个控件——要用数据绑定 + 观察者模式 + 异步更新
  • 大屏监控：可能会有上千个数据点同时刷新，UI 不能卡
  • 多显示器：生产看板、监控画面、调试窗口各占一块屏幕
  • 人机工程：颜色规范（红灯故障、黄灯预警、绿灯正常）、字体大小、操作防误触

🔵 业务逻辑层（最值钱的部分）

这是你和"拖控件选手"拉开差距的地方：

  • 设备管理：一个设备一个对象实例，管理它的状态、属性、生命周期
  • 协议路由：不同设备可能用不同协议，系统需要能统一接入、按需路由
  • 命令队列：下发给设备的指令不能丢了、不能乱序、要能取消
  • 报警引擎：条件触发（温度>80℃、压力<0.5MPa）、延时确认、分级报警、联动动作
  • 配方管理：不同产品对应不同工艺参数，一键切换

🟡 数据层

  • 实时库 vs 历史库：实时数据（高频写入）和历史数据（查询分析）应该分开
  • 缓存：设备状态读太快了？内存缓存扛住，不要每次都去问 PLC
  • 数据归档：一天几十 GB 的原始数据怎么压缩、怎么按时间分片

🟠 通信层（你最熟悉的 Modbus 就在这里）

  • Modbus RTU/TCP：你已知道基础，后面会深入：多站轮询、超时策略、广播模式
  • OPC UA：工业 4.0 标准协议，带安全认证和数据模型，现代上位机标配
  • 多协议并存：产线上可能既有 Modbus 设备又有 Siemens PLC，要用统一抽象层屏蔽差异
💡 面试亮点： "我的通信层设计了一个统一的 IDeviceDriver 接口，Modbus、OPC UA、S7 各自实现。上层业务不需要知道底层是走串口还是网口——面向接口编程。" —— 这句话值钱。

额外加分：那些"值更多钱"的系统维度

大多数人就讲到上面那几层就停了。下面这些才是区分 15K 和 25K 的分水岭：

⚡ 横切关注点
异常处理 & 防崩溃 日志 & 审计追踪 配置 & 热重载
🔧 质量属性
7×24 稳定性 实时性 & 低延迟 数据一致性 & 完整性
🏭 工程化
自动化测试 CI/CD 模拟器（没有硬件也能开发）

为什么这些值钱？

因为能写出 UI 的人很多，但能写出不出问题的系统的人很少。上位机跑在工厂里，死机一分钟可能损失几万块。面试官想听到你对以下问题的思考：

  • 防崩溃：串口断了怎么办？PLC 重启了怎么恢复？内存泄漏如何检测？
  • 日志审计：谁在什么时候改了哪个参数？——FDA 21 CFR Part 11 级别的追踪
  • 热重载：设备还在跑，我改个配置，不能重启软件
  • 模拟器：开发时 PLC 还没到货，你能自己写个模拟 PLC 数据的 Modbus Server

🎙️ 面试话术演练

面试官："说说你做的上位机系统？"

你的回答框架：

"我做的系统采用四层架构——UI 层（WinForms 数据绑定 + 异步刷新）、业务逻辑层（设备管理 + 命令队列 + 报警引擎）、通信层（抽象接口 IDeviceDriver，下挂 Modbus RTU/TCP 实现）、数据层（实时内存库 + SQLite 历史归档）。

通信层用生产者-消费者模式管理指令队列，避免 UI 线程阻塞。设备断线自动重试，最多 3 次间隔递增。所有模块通过依赖注入组装，方便单元测试和替换。

开发时用Modbus Slave 模拟器代替真实 PLC，通过 appsettings.json 一行配置切换模拟/真实模式。" —— 这段话落地，面试官已经在想给你多少钱了。

接下来的学习路线

基于这张地图，之后的课程会一一深入每个区块，但路线是这样规划的：

  1. 通信层深耕（当前项目的基础）—— Modbus RTU/TCP 深度实践、多设备轮询、异常处理
  2. 架构升级—— 生产者-消费者模式、依赖注入、接口抽象
  3. 业务逻辑层—— 设备管理、命令队列、报警引擎
  4. 数据层—— 实时库、历史归档、缓存策略
  5. UI 进阶—— 数据绑定、异步刷新、大屏监控
  6. 质量/工程化—— 模拟器、日志、热重载、测试
  7. 面试冲刺—— 话术打磨、项目亮点包装
