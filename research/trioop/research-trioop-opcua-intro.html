📡 OPC UA：工业 4.0 设备的"通用语言"

从概念到实操 · 从 S7 协议对比到 Trioop 项目接入 · 2026 年视角

一、OPC UA 是什么？一句话版

OPC UA（Open Platform Communications Unified Architecture，开放平台通信统一架构） 就是工业设备之间的"世界语"——让西门子、三菱、罗克韦尔、ABB 等不同品牌的 PLC、机器人、传感器、MES 系统，能用同一种语言安全地互相通信，而不需要每对设备写一套定制驱动。

它是 OPC 基金会（一个由全球工业自动化厂商组成的标准化组织）制定的标准，从 2008 年发布至今，已成为 工业 4.0 和智能制造的核心通信标准。

二、为什么需要 OPC UA？

2.1 问题：工业"方言"太多

工厂里真实的情况：

❌ 传统方式（没有 OPC UA）

你有一个西门子 S7-1200 和一个三菱 FX5U 要对话：

  • 西门子说 S7 协议（TCP 102 端口）
  • 三菱说 SLMP 协议（TCP 端口不定）
  • 两者之间需要一台协议转换网关
  • 或者写一个自定义程序：西门子端用 S7 读 → 转成三菱格式 → 三菱端写
  • 每加一个品牌就多一套适配代码

✅ 有 OPC UA 之后

所有设备都支持 OPC UA：

  • 每个设备都公开自己的 OPC UA 服务器地址
  • 任何客户端使用同一套 OPC UA 协议读写
  • 数据自带名字、类型、单位、描述——不需要查手册
  • 加新设备就像 U 盘即插即用
  • ERP/MES/SCADA 系统统一接入

三、OPC UA 的核心概念

3.1 地址空间（Address Space）—— 数据自带"简历"

Modbus 和 S7 传输的是"裸数据"：你给我 40001 寄存器，我告诉你值是 54.2。但 54.2 是什么？你得去查手册。

OPC UA 传输的是"结构化、自描述的数据模型"：

OPC UA 地址空间像一棵树（类似文件系统）：
Root
├── Objects
│   ├── 加热炉单元
│   │   ├── 加热区1
│   │   │   ├── 温度 (Float)     ← 值 185.3℃  ← 不只有数值，还有单位
│   │   │   ├── 目标温度 (Float) ← 值 190.0℃
│   │   │   ├── PID输出 (Float)  ← 值 72.5%
│   │   │   └── 过温报警 (Bool)  ← 值 False
│   │   ├── 加热区2
│   │   │   ├── 温度 ...
│   │   │   └── ...
│   │   └── 输送带
│   │       ├── 速度 ...
│   │       └── 启停 ...
│   └── 环境传感器
│       ├── 环境温度
│       └── 湿度
└── Types（类型定义）
    └── 加热区类型
        ├── 温度 : Float
        ├── 目标温度 : Float
        ├── PID输出 : Float
        └── 过温报警 : Bool

每个节点不只包含"值"，还包含元数据：

  • 名称（温度）
  • 数据类型（Float）
  • 单位（℃）
  • 范围（0~300）
  • 描述（"加热区2段实时温度"）
  • 读写权限（只读/可写）
  • 语义标签（isTemperature, isMeasurement）

3.2 订阅（Subscription）—— 数据变了才推

这是 OPC UA 相比 S7/Modbus 轮询最革命性的设计：

传统轮询（S7 / Modbus）： 客户端：温度多少？ ← 定期问，不管变没变 PLC： 185.3℃ 客户端：温度多少？ PLC： 185.3℃ ← 值没变也回答 客户端：温度多少？ ← 浪费带宽和 CPU PLC： 185.3℃ ↓ OPC UA 订阅模式： 客户端：订阅"温度"变量，变化超过 0.5℃ 时通知我 PLC： [静默...] ← 值没变，不说话 PLC： [静默...] PLC： 温度变为 187.1℃！ ← 值变了才推 PLC： 温度变为 190.5℃！ PLC： 温度变为 189.3℃！ 👉 带宽从"50 次/秒"降到"1~2 次/秒"但信息量更大

3.3 安全模型

安全等级传输认证签名场景
None明文匿名无调试、隔离网
Sign明文证书有工厂内网
SignAndEncryptAES 加密证书 + 密码有跨网络 / 云端
Basic256Sha256SHA-256 加密最强证书认证有安全要求最高

S7-1200 支持 None 到 Basic256Sha256 全部等级。

3.4 Pub/Sub（发布/订阅）—— 2025 新模式

除了传统的 C/S（客户端-服务器）模式，OPC UA 还有 Pub/Sub 模式：

  • 发布者（PLC）把数据发到 MQTT 或 UDP 多播
  • 订阅者（你的 App、数据库、云平台）各自订阅需要的数据
  • 解耦——发布者不需要知道谁在听，适合大规模的工业物联网
  • TSN 结合——配合时间敏感网络实现确定性低延迟（毫秒级）

4.2 TIA Portal 配置步骤

① CPU 属性 → OPC UA → 服务器：勾选"激活 OPC UA 服务器"，默认端口 4840
② 安全设置：调试阶段选"无安全"+"启用访客认证"（匿名）；生产环境换 Basic256Sha256
③ DB 块属性：右键 DB → 属性 → "可从 OPC UA 客户端读取" 打勾；每个变量 → "可从 HMI/OPC UA/Web 访问" 打勾

项目树 → OPC UA 通信 → 服务器接口 → 新建服务器接口
→ 把右侧想暴露的 DB/变量拖到左侧列表
→ 编译下载
⑤ 验证：用 UaExpert（免费 OPC UA 客户端）连 opc.tcp://192.168.0.1:4840，看看能不能看到变量树

4.3 Node.js (node-opcua) 代码示例

import { OPCUAClient, AttributeIds, makeBrowsePath } from 'node-opcua'

async function main() {
  const client = OPCUAClient.create({ endpointMustExist: false })
  await client.connect('opc.tcp://192.168.0.1:4840')
  const session = await client.createSession()

  // 浏览变量
  const browseResult = await session.browse('RootFolder')

  // 读取单个变量
  const dataValue = await session.read({
    nodeId: 'ns=3;s="MyDB"."temperature"',   // S7-1200 的 NodeId 格式
    attributeId: AttributeIds.Value,
  })
  console.log('温度:', dataValue.value.value)

  // ------------------
  // 订阅（关键优势）
  // ------------------
  const subscription = await session.createSubscription2({
    requestedPublishingInterval: 200,   // 200ms（S7-1200 最小支持 200ms）
    requestedLifetimeCount: 100,
    requestedMaxKeepAliveCount: 10,
  })

  const item = await subscription.monitor(
    { nodeId: 'ns=3;s="MyDB"."temperature"', attributeId: AttributeIds.Value },
    { samplingInterval: 200, queueSize: 1 },
  )

  item.on('changed', (dataValue) => {
    console.log('🔥 温度变了:', dataValue.value.value)
  })

  // 等待一会
  await new Promise(r => setTimeout(r, 30000))

  await subscription.terminate()
  await session.close()
  await client.disconnect()
}

五、回到 Trioop：OPC UA 适合我们吗？

5.1 OPC UA 订阅 vs 你们现在的 NodeS7 轮询

带宽占用固定不变——数据没变也浪费数据不变时几乎 0

跨品牌访问只能连西门子任何 OPC UA 设备

六、结论：要不要上 OPC UA？

✅ OPC UA 适合你如果……

  • 你希望数据 自带语义（不只用 IB0/QB0/DB1 这种数字，而是用温度/压力/速度等名称）
  • 你有 多个系统 要同时访问 PLC 数据（SCADA + 自己的 Web App + MES + 数据库）
  • 你有 安全要求（网络暴露到外部，需要认证和加密）
  • 你不需要 极高频率（200ms 以上够用）
  • 你愿意在 TIA Portal 里配置 OPC UA Server

❌ OPC UA 不适合你如果……

  • 你的目标是 20ms（50Hz）或更快的更新——S7-1200 OPC UA 最小间隔 200ms，物理上做不到
  • 你只想 监控 I/Q 点位 + 少量 DB 变量——NodeS7 的简单轮询已经够用
  • 你不想 / 不能改 TIA Portal 配置（比如 PLC 已经在生产运行）
  • 你需要 写 Q 点位（物理输出）——OPC UA 不支持直接写过程映像区

🏆 给 Trioop 的建议

现在不动，但为将来留接口：

① 保持 NodeS7 轮询作为主要通信方式（你们已经调试好了）
② 预留 OPC UA 客户端的开关——以后如果想接入其他系统，可以同时启用
③ 关键的数据库变量，如果 S7-1200 配置了 OPC UA，可以用订阅模式 "双通道" 获取，NodeS7 做 I/Q 区高频监控，OPC UA 做 DB 变量慢速语义化读取

这种 混合架构 是最实际的：NodeS7 负责 速度和灵活，OPC UA 负责 标准化和语义。
