一套给开发者界面的克制系统

Geist 的重点不是制造品牌视觉，而是把界面压回到清晰、可读、可维护：同名 token 管住明暗主题，灰阶承担层级，强调色只表达状态和少数关键动作。

核心判断

Vercel 这套规范本质上是“开发工具审美”的工程化表达：高对比、低装饰、强 token、轻动效、强文案约束。它适合控制台、SaaS、配置面板、技术文档和 AI 工具界面，不适合需要强情绪化营销视觉的场景。

01

Token 先于组件

颜色、字号、间距、半径、组件尺寸都先被命名，再被组件引用。价值在于明暗主题和状态变化可以稳定替换。

02

灰阶负责大部分表达

信息层级主要靠 gray 与 alpha gray。强调色不是装饰材料，而是状态、链接、聚焦和关键操作的信号。

03

排版是界面骨架

Sans 管 UI 与正文，Mono 管代码和数据。copy 与 label 分开，避免多行正文被压成控件文字的节奏。

04

体验偏向即时反馈

规范明确允许 0ms。动效只在揭示变化时出现，强调短、物理、可被关闭，而不是制造注意力。

同名 Token，双主题换值

Light 与 Dark 的关键是“名字不变，值改变”。组件引用 primary、background-100、gray-1000 等语义名，而不是在业务代码里到处写黑白色值。

排版把界面分成三种阅读模式

Heading 负责结构和标题，Label 负责单行可扫读信息，Copy 负责多行正文。这个区分比单纯给字号命名更有工程价值。

heading-40 Deployment Summary 大区块
heading-24 Runtime Logs 卡片标题
copy-16 Use copy tokens for multi-line reading. The line height is intentionally taller than labels. 正文
label-14 Environment Variables 导航/表头
copy-13-mono p95_latency_ms = 128.44 代码/数据
大号标题收紧字距

规范里的 heading token 随字号变大而负向 letter-spacing 更明显，使标题更像一个整体。

copy-14 与 label-14 是默认主力

多数界面文字落在 14px，靠 line-height 和职责区分阅读节奏。

Mono 只在信息结构需要时出现

代码、路径、构建日志、数值对齐适合 Mono；普通说明继续用 Sans。

不要手写字号组合

使用 token 可以避免同一页面出现过多字重、行高和层级噪音。

布局节奏是 4px 的倍数

规范给出的实用节奏是 8px 组内、16px 组间、32-40px 区块间。页面容器以 1200px 为中心列，断点覆盖移动端到 2xl。

组件只是 Token 的具象化

按钮和输入框没有复杂造型：40px 默认高度、6px 半径、少量 padding。状态变化沿着色阶前进，聚焦态用双层 ring 保证可访问性。

Controls

Primary 只给当前视图最重要动作；Error 只给破坏性动作。

State Progression

同一元素的 hover、active、focus 不是随机变色，而是按 token 阶梯推进。

default 100/400
hover 200/500
active 300/600
focus 2+2 ring

文案也是设计系统

Geist 对文案的约束很强：按钮是“动词 + 名词”，错误是“发生了什么 + 下一步”，Toast 说具体变化，不说 successfully。

动作要具体

不要用 Confirm、OK 或孤立动词。动作名本身要让用户知道会影响什么对象。

Deploy Project
Delete Member
Invite Teammate

错误要可处理

错误不是情绪提示，而是诊断信息。先说事实，再给下一步。

Build failed. Bundle exceeds 50 MB. Reduce it or raise the limit.

反馈要少废话

Toast 去掉句号，去掉 successfully，直接命名改变的对象。

Project deleted
Domain added
Environment variable saved

落地时的取舍

如果把这套规范用于自己的产品，重点不是照抄 Vercel 的黑白外观，而是复用它的约束方式：少变量、强语义、强可访问性、少装饰。

建议做

  • 用 gray-1000、900、700 排出主次禁用层级。
  • 把强调色留给状态、链接、focus 和单一主操作。
  • 每个交互元素保留 :focus-visible 可见焦点环。
  • 文案用具体对象命名动作和结果。
  • 用同名 token 支撑明暗主题，而不是两套组件。

不要做

  • 不要把 background-200 当万能浅灰填充。
  • 不要用颜色单独表达状态，要配图标或文字。
  • 不要在同一视图混用过多圆角、字重和阴影。
  • 不要手写散落的字号、行高和按钮尺寸。
  • 不要用长循环动画或强装饰打断任务流。
