五、面试高频问题与回答

1. 为什么 PLC 通讯要串行化？

单个 S7 连接通常不适合多个线程同时读写。并发访问可能导致响应错乱、超时或连接异常。所以我会对底层 PLC 客户端加锁，或者使用队列统一调度读写；高频采集和低频写入也可以拆独立连接，但要避免命令互相覆盖。

2. 如何减少 PLC 读取压力？

按区域批量读取，合并连续地址；DB 大变量分时轮转；设置合理轮询周期；失败后退避；只把变化项通知 UI、报警和历史记录模块。

3. BOOL / REAL / DINT 怎么解析？

S7 数据按大端组织，BOOL 要处理字节偏移和 bit 偏移，REAL 是 IEEE754 浮点，DINT 是 4 字节有符号整数。PC 端通常是小端，需要做字节序转换。

4. WCS 和 WMS 的区别？

WMS 负责库存、订单、库位策略和业务规则；WCS 负责设备执行，把 WMS 的任务拆成输送线、提升机、堆垛机等设备动作，并实时采集状态、处理异常、回传结果。

5. 出库任务异常怎么办？

任务要落库并有状态机。设备故障、条码不符、库位占用、超时都要记录错误码、报警、允许人工干预。恢复后要能续跑、重试、取消或重新下发，不能只靠内存状态。

6. ASP.NET Core 和 Vue 不是你的强项怎么办？

可以这样回答：Vue 我有 React/TypeScript 基础，上手页面开发问题不大；ASP.NET Core 我需要补框架细节，但我理解 WebAPI、数据库、接口协议、异步任务和工程化。我的优势是能把软件接口和现场 PLC/设备联调结合起来。

六、WCS 流程话术

“以入库为例，WMS 下发入库任务，WCS 先校验托盘号、物料、目标库位和设备可用状态，然后把任务拆成输送线动作、提升机动作、堆垛机取放货动作。WCS 通过 PLC 命令区写入任务号、目标地址和动作码，同时轮询 PLC 状态区。设备完成后，WCS 更新任务状态、落库并回传 WMS。如果扫码不一致、库位占用、设备故障或超时，就进入异常状态，报警并等待人工处理。”
