一、先给判断

这个岗位的本质：不是纯后端，也不是纯上位机，而是 WCS 设备控制层开发。上接 WMS/MES/ERP/SAP，下接 PLC、输送线、堆垛机、提升机、AGV/RGV、扫码枪、传感器和现场电控系统。

你的胜负手：不要硬装“资深 WCS”。你要把自己定位成“有完整编程底子、能快速补 WebAPI/Vue、已经做过 S7/Modbus/上位机轮询/报警/配方，愿意下现场联调的转型型候选人”。

最该准备

  • C# Task、取消、超时、队列、锁。
  • ASP.NET Core WebAPI 基础。
  • S7 DB/I/Q/M 读写和字节序。
  • WMS 到 WCS 到 PLC 的任务流。

最该展示

  • 你能把设备通讯讲清楚。
  • 你能把异常恢复讲清楚。
  • 你能把项目落地讲清楚。
  • 你能接受出差和现场压力。

最该确认

  • 是不是长期驻场。
  • 是否需要改 PLC 程序。
  • 项目是否自研产品还是外包实施。
  • 薪资是否含出差补贴、加班和年终。

行业前景

智能仓储和产线物流自动化仍有需求，尤其是制造业、医药、冷链、新能源、重工、军工/央国企供应链。WCS 这类岗位的长期价值在于“懂软件 + 懂设备 + 懂现场流程”，比普通 CRUD 后端更稀缺。

但集成商项目制也有明显代价：需求定制多、现场不可控、验收压力大、出差频繁。前景好不好，关键看公司是否有标准化产品、是否沉淀 WCS 平台，而不是每个项目从头堆代码。

四、技术准备优先级

1C# Task 与后台调度

必须能讲清：为什么 PLC 连接不能随便并发读写；如何用锁、队列或 SemaphoreSlim 串行化；如何用 CancellationToken 停止轮询；如何处理超时、重试、断线重连和异常日志。

面试话术：单个 S7 连接我会按串行化处理，避免多线程同时读写导致响应错乱。高频采集走固定轮询，控制命令走队列并设置超时和重试；后台任务支持取消，异常只影响当前周期，不让整个服务挂掉。

2ASP.NET Core WebAPI

补到能说：Controller、DTO、依赖注入、中间件、全局异常、日志、Swagger、认证授权、后台服务、SignalR。不要深挖框架源码，先能把 WCS 接口设计讲出来。

接口 用途
POST /api/tasks/inbound WMS 下发入库任务，包含托盘号、物料、批次、目标库位。
GET /api/tasks/{id} 查询任务状态：待执行、运行中、完成、失败、人工处理。
GET /api/devices 查询堆垛机、提升机、输送线、扫码设备状态。
POST /api/tasks/{id}/cancel 取消任务或进入人工干预流程。
GET /api/alarms 报警列表、确认、搁置、恢复、导出。

3S7 / PLC 通讯

  • S7-1200/1500 常用 ISO-on-TCP，端口 102，Rack/Slot 通常 0/1 或按设备配置。
  • WCS 常见做法是 PLC DB 中定义命令区、状态区、心跳、任务号、错误码。
  • REAL、DINT、INT、WORD 要注意 S7 大端字节序，BOOL 要注意 byte.bit。
  • 读数据要批量合并地址，写命令要有握手，避免重复下发或漏确认。

4WCS 业务流程

标准入库流程：WMS 下发入库任务 → WCS 校验托盘/物料/库位/设备状态 → 分解输送线、提升机、堆垛机动作 → 写 PLC 命令区 → 轮询状态区 → 完成后回传 WMS → 异常进入报警和人工干预。

你要熟悉：入库、出库、移库、盘点、空托盘、条码不符、库位占用、设备故障、断点续传。

五、结合 WpfScada 的项目讲法

“我这个 WPF SCADA 项目主要验证了 WCS 底层会用到的能力：PLC 通讯、轮询调度、DB 变量解析、报警、配方参数下发、Modbus 设备接入。它不是完整立体库 WCS，但和 WCS 在底层设备对接上的问题一致：连接串行化、状态轮询、异常恢复、报警生命周期和参数写入。”

六、面试高频回答

1. 你没有完整 WCS 项目经验，为什么能做？

答：我不是把自己定位成资深 WCS 架构师，而是能进入 WCS 设备控制层的开发者。我有前后端工程能力，也做过 WPF 上位机、S7/Modbus 通讯、DB 变量解析、轮询调度、报警和配方上下传。WCS 的业务流程我正在补，但底层设备对接、异常处理和现场联调的基础已经具备。

2. WCS 和 WMS 的区别是什么？

答：WMS 管库存、订单、库位策略和业务规则；WCS 管设备执行，把 WMS 的任务拆解成 PLC、输送线、提升机、堆垛机、AGV/RGV 等设备动作，同时采集设备状态、处理异常并回传任务结果。

3. 如何设计 WCS 和 PLC 的通讯？

答：我会和 PLC 约定命令区、状态区、心跳区、报警区。命令区包含任务号、动作码、目标地址、参数和触发位；状态区包含设备模式、运行状态、当前位置、完成位、错误码。写命令后等待 PLC 确认，任务号用于幂等和防重复。

4. 任务异常如何恢复？

答：任务必须落库，有状态机和操作日志。条码不符、库位占用、设备故障、超时都进入异常状态并报警。人工处理后可以重试、跳过、取消或重新下发。系统重启后从数据库恢复未完成任务，而不是只依赖内存。

5. Vue/ASP.NET Core 不是你主项怎么办？

答：Vue 对我来说迁移成本低，我有 React/TypeScript 基础；ASP.NET Core 我需要补一些框架细节，但 WebAPI、接口设计、数据库、异步任务、日志和工程化思路是通的。我真正的优势是能把软件开发和 PLC/设备现场问题连起来。

  1. 公司是否有 WCS 平台产品和代码规范？新人能否参与核心模块设计，而不只是现场改 bug？
  2. 试用期考核标准是什么？以代码交付、现场调试、项目验收还是出差配合为主？
  3. 薪资结构是 12 薪、13 薪还是有项目奖金？出差补贴、加班调休如何计算？

八、工作强度与薪资大概

工作强度判断

岗位 JD 明确写“经常性出差”，再结合公司业务是自动化仓储/智能物流集成，强度大概率不是普通办公室研发。主要压力来自现场联调、客户验收、设备异常、跨专业沟通和售后响应。

强度来源 具体表现 必须问清
项目现场 单机调试、联机联调、陪产、验收。 每月出差天数、单次驻场周期、是否全国出差。
设备不可控 PLC、电气、机械、网络、扫码、传感器任何一环都会影响软件。 现场是否有 PLC/电气/机械同事配合。
客户验收 试运行期间故障要快速定位，可能晚间或周末处理。 加班是否调休、售后响应是否轮值。
项目制交付 需求变更、接口变更、现场临时改逻辑常见。 是否有需求文档、通讯协议文档、版本管理流程。

薪资判断

公开招聘数据不完全一致，只能给谈判区间。智联页面中 WCS 资深软件工程师有 1.5-2.3 万/月的样本，WMS/WCS 软件开发有 1-1.6 万/月样本；北京普通 .NET/C# 岗位跨度更大，但和 WCS 现场出差岗不能直接等同。

底线 10-12K

如果对方认为你是转型初级、需要培养，可能压到这个区间。除非补贴好、成长明确，否则不太建议低于这个区间接受高强度出差。

合理目标 12-16K

结合你有编程经验、上位机项目、S7/Modbus 基础，但 WCS 经验不足，这个区间比较现实。若出差频繁，应往上谈。

进攻报价 16-20K

如果你面试中把项目、PLC 通讯、现场适应能力讲得很稳，并且岗位需要独立开发和长期出差，可以尝试这个区间。

建议话术：我更看重岗位是否能深入 WCS 和设备控制，但因为这个岗位包含现场出差和联调压力，我期望月薪在 15K 左右，具体可以结合出差补贴、年终、试用期和职责范围综合看。

九、个人职业成长：机会与风险

成长机会

  • 从前端/全栈转入工业软件，形成差异化竞争力。
  • 补齐 PLC、设备协议、现场联调和 WCS 业务流程。
  • 未来可走 WCS 模块负责人、项目技术负责人、自动化软件架构方向。
  • 懂 C#、WebAPI、Vue、PLC 的复合型人选在智能仓储里有价值。

主要风险

  • 如果公司项目制太重，可能长期现场救火，代码能力成长慢。
  • 如果没有标准产品和规范，你会反复做定制改动。
  • 长期出差会影响学习节奏、生活稳定和健康。
  • 如果只是实施/售后，不参与核心 WCS 设计，履历含金量会下降。

入职前判断标准

  • 能看到代码规范、通讯协议模板、项目文档、版本管理流程，是好信号。
  • 有人带你熟悉业务，并且能参与核心模块，是好信号。
  • 只强调“能出差、能吃苦、现场解决问题”，但不讲技术体系，是风险信号。
  • 薪资不高但出差补贴、调休、项目奖金含糊，是风险信号。
