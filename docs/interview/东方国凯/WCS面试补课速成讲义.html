二、C# Task：把它当成“后台工人”来理解

1. Task 是什么

你可以把 Task 理解成一个“正在做或将要做的工作”。比如 WCS 程序里有很多后台工作：每 200ms 读 PLC 状态、每 1 秒检查任务超时、收到 WMS 任务后下发给设备、写日志、保存报警。

这些工作不能都堵在 UI 或接口线程里，所以要交给后台任务执行。

2. async / await 是什么

async 表示这个方法里面可能有异步等待；await 表示“等这个耗时操作完成，但不要傻站着占住线程”。

public async Task<string> GetDeviceStatusAsync()
{
    // 等 PLC 或 HTTP 返回时，不阻塞当前线程
    string status = await ReadStatusFromDeviceAsync();
    return status;
}

面试话术：await 不是新开线程，它是把后续逻辑挂起，等异步操作完成后再继续执行。这样可以提高并发能力，避免线程被 IO 等待浪费。

3. Task.Run 什么时候用

Task.Run 是把一段 CPU 工作丢到线程池。比如大量计算、解析大文件可以用。读数据库、HTTP 请求、Socket 读写通常优先用原生异步 API，不要随便包 Task.Run。

// 可以：后台循环任务
_backgroundTask = Task.Run(() => PollingLoopAsync(_cts.Token));

// 不推荐：已有异步 API 又包一层 Task.Run
await Task.Run(() => httpClient.GetAsync(url));

4. CancellationToken：给后台任务一个“停止信号”

现场软件一定要能优雅停止。比如用户点击“停止轮询”，程序不能粗暴杀线程，而是发一个取消信号，让循环自己退出。

private CancellationTokenSource? _cts;

public void Start()
{
    _cts = new CancellationTokenSource();
    _ = Task.Run(() => PollingLoopAsync(_cts.Token));
}

public void Stop()
{
    _cts?.Cancel();
}

private async Task PollingLoopAsync(CancellationToken token)
{
    while (!token.IsCancellationRequested)
    {
        await ReadPlcOnceAsync(token);
        await Task.Delay(200, token);
    }
}

面试话术：后台轮询必须支持取消，否则程序关闭、切换 PLC、停止监控时容易残留任务，导致重复读写或资源泄漏。

5. SemaphoreSlim / lock：为什么 PLC 读写要排队

很多 PLC 通讯库的单个连接不适合多线程同时读写。你可以理解成一条电话线：A 正在问 PLC 一个问题，B 又插进来问另一个问题，回复就可能乱。

private readonly SemaphoreSlim _plcLock = new(1, 1);

public async Task<byte[]?> ReadDbAsync(int db, int start, int length)
{
    await _plcLock.WaitAsync();
    try
    {
        return await _plc.ReadDbAsync(db, start, length);
    }
    finally
    {
        _plcLock.Release();
    }
}

面试话术：我会把单个 PLC 连接的读写串行化。高频采集走固定轮询，控制命令走队列，必要时拆多个独立连接，但不会让多个线程乱写同一个连接。

6. 超时、重试和退避

现场网络不稳定，PLC 可能断线，不能一个读取卡死整个系统。常用做法：

  • 每次请求设置超时，例如 2 秒。
  • 失败后记录错误，不要让后台任务崩溃。
  • 连续失败后降低轮询频率，避免疯狂打 PLC。
  • 重连时用退避：1 秒、2 秒、4 秒、8 秒，最多 30 秒。
try
{
    using var timeoutCts = new CancellationTokenSource(TimeSpan.FromSeconds(2));
    await ReadPlcOnceAsync(timeoutCts.Token);
    failureCount = 0;
}
catch (Exception ex)
{
    failureCount++;
    logger.LogWarning(ex, "PLC read failed");
    await Task.Delay(Math.Min(30000, 1000 * failureCount));
}

7. 面试必须会答的 Task 问题

问题短答案
Task 和线程一样吗？不一样。Task 是一个异步工作的抽象，可能在线程池线程上执行，也可能只是 IO 等待的状态机。
await 会阻塞线程吗？不会像同步等待那样阻塞线程。它会释放当前线程，等任务完成后继续执行。
为什么不要用 .Result / .Wait()？容易造成死锁或线程池阻塞，尤其在 UI 和 ASP.NET 环境中。
后台轮询怎么停止？用 CancellationToken，循环里检查取消信号，所有延迟和 IO 都传 token。
PLC 并发读写怎么控制？用 lock、SemaphoreSlim 或队列，把同一连接上的读写串行化。

三、ASP.NET Core WebAPI：把它当成“WCS 对外窗口”

1. WebAPI 在 WCS 里干什么

WCS 不是孤立程序。它要和 WMS/MES/ERP、前端看板、移动端、报表系统交互。WebAPI 就是这些系统访问 WCS 的入口。

WMS 下发任务 → WebAPI 接收 → WCS 存库并调度 → PLC 执行 → WebAPI 回传状态

2. Controller 是什么

Controller 是接口入口。别人请求一个 URL，就会进入对应的方法。

[ApiController]
[Route("api/tasks")]
public class TasksController : ControllerBase
{
    [HttpPost("inbound")]
    public async Task<IActionResult> CreateInboundTask(CreateInboundTaskDto dto)
    {
        // 1. 校验参数
        // 2. 保存任务
        // 3. 通知调度服务
        return Ok(new { taskId = "T20260708001" });
    }
}

3. DTO 是什么

DTO 是接口收发的数据结构。不要直接把数据库实体暴露给外部系统。

public class CreateInboundTaskDto
{
    public string PalletCode { get; set; } = "";
    public string MaterialCode { get; set; } = "";
    public string TargetLocation { get; set; } = "";
}

4. 依赖注入 DI 是什么

你不要在 Controller 里手动 new 一堆服务，而是让框架帮你创建并传进来。

builder.Services.AddSingleton<PlcService>();
builder.Services.AddScoped<TaskService>();

public class TasksController : ControllerBase
{
    private readonly TaskService _taskService;

    public TasksController(TaskService taskService)
    {
        _taskService = taskService;
    }
}
生命周期含义例子
Singleton整个程序只有一个实例。PLC 连接管理、后台调度器、配置服务。
Scoped一次 HTTP 请求一个实例。业务服务、数据库上下文。
Transient每次使用都创建新实例。轻量工具类。

5. Middleware 是什么

中间件像流水线。请求进来要经过认证、日志、异常处理、路由，最后到 Controller。

请求 → 异常处理中间件 → 日志 → 鉴权 → 路由 → Controller → 响应

面试话术：WCS 的 WebAPI 我会统一做日志、异常处理和鉴权。设备控制类接口还要做幂等校验，避免 WMS 重复请求导致任务重复下发。

6. WCS 常见接口

接口作用要点
POST /api/tasks/inbound入库任务下发。校验托盘、物料、目标库位，生成任务号。
POST /api/tasks/outbound出库任务下发。校验库存、锁定库位，生成取货路径。
GET /api/tasks/{id}任务状态查询。返回 Created/Running/Completed/Failed。
POST /api/tasks/{id}/cancel取消任务。判断任务是否已下发给设备，避免危险取消。
GET /api/devices设备状态。堆垛机、提升机、输送线、扫码枪在线状态。
GET /api/alarms报警列表。支持确认、恢复、导出。

7. BackgroundService

ASP.NET Core 不只会接接口，也能跑后台任务。WCS 里常见后台服务：PLC 轮询、任务调度、报警扫描、心跳检查。

public class PlcPollingWorker : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            await ReadPlcStatusAsync(stoppingToken);
            await Task.Delay(200, stoppingToken);
        }
    }
}

8. SignalR 是什么

普通 HTTP 是前端问一次，后端答一次。设备状态是实时变化的，前端不能一直疯狂刷新。SignalR 可以让后端主动推送状态给前端。

面试话术：任务进度和设备状态可以通过 SignalR 推送到 Vue 看板，避免前端高频轮询，同时让报警和状态变化更及时。

五、S7 / PLC 通讯：你必须会讲的工业基础

1. PLC 是什么

PLC 是工业现场的控制器。你可以把它理解成“设备的大脑”。WCS 不会直接控制电机，而是给 PLC 写命令，PLC 再控制堆垛机、提升机、输送线、电机、气缸、传感器。

WCS 软件 → PLC 命令区 → PLC 程序 → 变频器/伺服/传感器 → PLC 状态区 → WCS 软件

2. S7-1200/1500 通讯基础

  • 常用协议：S7 ISO-on-TCP。
  • 默认端口：102。
  • 常见库：Sharp7、S7.NetPlus、西门子官方 OPC UA。
  • 常读区域：I 输入区、Q 输出区、M 中间区、DB 数据块。

3. I/Q/M/DB 是什么

区域含义例子
I输入区，外部信号进入 PLC。传感器到位、急停按钮、光电开关。
Q输出区，PLC 控制外部设备。电机启动、指示灯、阀门输出。
M中间存储区，PLC 内部状态。临时标志、运行状态。
DB数据块，结构化数据。任务号、目标库位、设备状态、报警码。

4. DB 通讯协议怎么设计

WCS 和 PLC 通常会约定一块 DB，分成命令区和状态区。

字段类型用途
TaskIdDINT/String任务号，防重复、做追踪。
CommandCodeINT动作码，比如入库、出库、取货、放货。
TargetLocationINT/String目标库位。
CommandTriggerBOOLWCS 写 1，表示新命令。
CommandAckBOOLPLC 写 1，表示收到命令。
DoneBOOLPLC 写 1，表示动作完成。
ErrorCodeINT故障码。
HeartbeatBOOL/INT心跳，判断通讯是否正常。

5. 字节序：为什么 REAL/DINT 容易读错

西门子 S7 数据通常是大端。普通 PC 是小端。如果你直接拿字节转数字，可能读出奇怪的值。

REAL 12.34 在 PLC 中是 4 个字节；读取后要按正确字节序转成 float。

面试话术：S7 的多字节数据要注意大端字节序。BOOL 还要处理 byte.bit 偏移，不能只按字节读。我的项目里把数据类型解码集中在 S7Service，避免各页面重复写转换逻辑。

6. 心跳和断线重连

心跳就是双方互相证明“我还活着”。常见做法：WCS 定时翻转一个 bit 或递增一个计数；PLC 检测这个值是否变化。WCS 也检测 PLC 心跳是否变化。

  • 心跳正常：继续运行。
  • 心跳超时：报警，停止下发新任务。
  • 断线恢复：重新连接，读取当前设备状态和未完成任务。

7. 为什么要合并地址读取

读 PLC 一次有通讯开销。如果你分别读 DB1.DBW0、DB1.DBW2、DB1.DBW4，会产生 3 次请求。更好的方式是一次读取 DB1 从 0 开始的 6 个字节，然后本地拆解。

面试话术：我会把连续地址合并读取，降低通讯次数。I/Q/M 高频区独立轮询，DB 大块数据分时轮转，避免一次读太多导致周期变长。

六、WCS 业务：把仓库任务变成设备动作

1. WMS、WCS、PLC 分别干什么

系统一句话理解例子
WMS管库存和业务策略。哪个托盘在哪个库位，哪个订单要出哪些货。
WCS管设备执行。让堆垛机去 A01 取货，再送到出库口。
PLC管具体动作。电机转、提升机升降、传感器判断到位。

2. 入库流程

  1. 托盘进入入库口，扫码枪读取托盘码。
  2. WCS 向 WMS 查询或接收入库任务。
  3. WCS 判断目标库位、设备是否空闲、路径是否可用。
  4. WCS 给输送线 PLC 下发放行命令。
  5. 提升机/堆垛机接到任务，把托盘送到目标库位。
  6. PLC 返回完成信号。
  7. WCS 更新任务状态并回传 WMS。

3. 出库流程

  1. WMS 下发出库任务，包含物料、数量、目标出库口。
  2. WCS 锁定库存和库位，生成设备任务。
  3. 堆垛机去库位取货。
  4. 提升机/输送线把货送到出库口。
  5. 扫码复核，确认托盘或物料正确。
  6. WCS 回传出库完成。

4. 任务状态机

状态机就是任务从开始到结束会经历的状态。

Created → Checked → Dispatched → Running → Completed
Running → Failed → ManualHandling → Retry/Cancel/Completed
状态含义
Created任务已创建，但还没下发设备。
Dispatched任务已经写入 PLC 或设备控制系统。
Running设备正在执行。
Completed任务完成，已回传。
Failed任务失败，需要处理。
ManualHandling人工干预中。
Cancelled任务取消。

5. 常见异常怎么处理

异常处理思路
条码不一致暂停任务，报警，等待人工确认是改任务、退回还是放行。
库位占用重新分配库位，或人工确认库位状态。
设备故障任务进入 Failed，记录错误码，设备恢复后支持重试或续跑。
通讯断线停止下发新任务，重连后读取 PLC 当前状态，再决定恢复策略。
任务超时报警，检查设备状态，避免重复下发同一任务。

6. 断点续传是什么

断点续传不是文件下载专用概念。在 WCS 里，它表示系统中断后能知道任务执行到哪一步，然后从合理位置继续或人工处理。

面试话术：WCS 任务不能只存在内存里，必须落库。系统重启后先恢复未完成任务，再读取 PLC/设备状态，判断任务是继续、重试、取消还是人工接管。

八、面试常见问题：直接背这个框架

1. 为什么转 WCS / 工业软件？

答：我之前有前端/全栈经验，工程化和编程基础比较扎实。后来系统学习了 PLC、电气和上位机，发现工业软件更需要软件能力和现场理解的结合。我希望往 WCS、上位机、设备通讯这个方向长期发展。

2. 你最大的短板是什么？

答：完整商业 WCS 项目经验还不够，尤其是库位策略、堆垛机调度和项目验收流程需要在真实项目里补。但我的优势是学习快，能写代码，也已经做过 S7/Modbus、轮询、报警、配方这些底层模块。

3. 如果 PLC 读写很慢怎么办？

答：先定位是网络、PLC 响应、读取地址分散还是程序阻塞。优化上会合并连续地址、减少无效轮询、分层采集高低频数据、设置超时和失败退避，必要时拆分连接或调整 PLC 数据区设计。

4. 如果 WMS 重复下发同一任务怎么办？

答：任务接口要做幂等。用外部任务号或业务唯一键判断是否已存在；已经存在则返回当前任务状态，不能重复创建和重复下发设备。

5. 如果设备执行到一半系统重启怎么办？

答：任务状态必须落库。系统启动后读取未完成任务，再读取 PLC 当前状态，判断设备是否仍在执行、已完成还是故障。不能直接重发命令，要结合任务号和 PLC 状态做恢复。

“我是前端/全栈背景转上位机和工业软件方向。我的优势是编程基础比较扎实，能做前后端，也已经做过 WPF 上位机、S7/Modbus 通讯、PLC 数据轮询、报警、配方参数上下传。WCS 业务我不是资深，但我理解它是 WMS 和设备执行层之间的控制系统，我愿意从设备通讯、接口开发、现场联调切入，把 WCS 业务补起来。”

你要问对方的问题

  1. 贵公司的 WCS 是标准产品二开，还是每个项目定制开发？
  2. WCS 和 WMS/MES 的接口通常是 HTTP、WebService、数据库中间表，还是消息队列？
  3. PLC 侧是否有统一 DB 通讯规范，比如命令区、状态区、心跳、任务号、错误码？
  4. 堆垛机和提升机是通过 PLC 间接控制，还是厂家提供 TCP/Modbus/专有协议？
  5. 这个岗位是否需要修改 PLC 程序，还是主要负责 WCS 软件和接口？
  6. 平均每月出差多少天？单次驻场周期多长？出差补贴和调休怎么计算？
  7. 新人入职后会参与核心模块开发，还是主要做现场实施和售后？

临场不要踩的坑

  • 不要说自己“精通 WCS”，说“我能从设备通讯和接口开发切入”。
  • 不要只讲 UI，要讲 PLC 通讯、任务状态、异常恢复。
  • 不会的问题不要硬编，可以说“这个我没有在真实项目里完整做过，但我的理解是……”然后讲思路。
  • 出差可以接受，但一定要问补贴、周期、调休和售后响应。
