❓面试大概率遇到的 15 个技术问题

Modbus 协议

Q1：Modbus RTU 和 TCP 有什么区别？
要点：TCP 有 7 字节 MBAP 头（Transaction ID + Protocol ID + Length + Unit ID），无 CRC；RTU 无 MBAP，但有 CRC16 校验（多项式 0x8005 反转 0xA001）。
你的代码：BuildRTUFrame() vs BuildTCPFrame() 分两条路径，ParseResponse() 中 TCP 先跳过 MBAP 头再解析。
Q2：Modbus 功能码有哪些？为什么只实现了读功能码？
准备回答："01 读线圈、02 读离散输入、03 读保持寄存器、04 读输入寄存器、05 写单线圈、06 写单寄存器、15 写多线圈、16 写多寄存器。目前读功能码已经完整实现，写功能码的协议层（帧组装）设计好了，UI 层交互还没做——因为当前项目示例以监控为主。如果需要，我可以很快补上写入功能。"
⚠️ 建议面试前把写功能码实现补上。
Q3：CRC16 怎么算的？为什么校验失败要丢弃数据？
要点：初始值 0xFFFF，异或每个字节，右移 8 轮，多项式 0xA001。校验失败→数据可能在传输中损坏→必须丢弃。
你的代码：ModbusProtocol.CalcCRC() + VerifyCRC()，在 Sp_DataReceived 中校验失败直接 return 不触发事件。
Q4：Modbus 单次最多读多少个数据？
要点：保持/输入寄存器 ≤125，线圈/离散输入 ≤2000。超过协议上限会怎样？从站返回异常码 03（非法数据值）。
你的代码：MAX_REGISTERS_PER_READ = 125 + GetMaxCount() 校验 + UI 弹窗提示。

C# 核心技术

Q5：委托、事件、Lambda —— 它们在项目中怎么用的？
要点：委托 = 类型安全的函数指针。事件 = 委托的封装，只能 +=/-= 不能直接调用。Lambda = 匿名方法。
项目中：public event Action<byte[], bool>? FrameReceived（事件）、Func<bool> _isTcpMode（委托回调）、btn.Click += (s, e) => ...（Lambda）。
进阶回答：事件相比直接委托调用，外部不能 = null 或 .Invoke()，符合封装原则。
Q6：你用了哪些线程同步机制？为什么串口轮询不能用多线程？
要点：ConcurrentQueue（无锁队列）、ManualResetEventSlim（同步等待）、lock（临界区）、Interlocked（原子计数）。
串口是半双工，多线程同时写会数据错乱。用生产者-消费者队列将所有读写请求串行化，避免锁竞争。
你的代码：ModbusPollingService 的 ConsumerLoop() + AutoResetEvent 唤醒。
Q7：IDisposable 模式怎么实现的？
要点：通过 Dispose() 释放非托管资源（串口、TCP 连接、事件句柄）。设置 _disposed 标志防止重复释放。
你的代码：ModbusTransport.Dispose() → 依次断开 TCP、关闭串口。ModbusPollingService.Dispose() → 停止消费者线程、释放 AutoResetEvent。
Q8：WPF 的 MVVM 模式怎么用的？
要点：View（XAML）←Binding→ ViewModel（INotifyPropertyChanged）←→ Model。
你的代码：BitViewModel + ByteRowViewModel 实现 INotifyPropertyChanged，BoolToBackgroundConverter 转换器，ItemsControl + DataTemplate 数据绑定。
记住：可以主动说 ThreeWay vs TwoWay vs OneTime 的区别！

⚙️ 工业上位机实践

Q9：工程值转换（Scale + Offset）是怎么做的？
要点：PLC 读到的是原始值（raw value）→ 实际值 = raw × scale + offset。例如 4-20mA 电流环 → 0-100 压力值。
你的代码：RecipeManager.DownloadRecipeAsync() 中有 rawValue = (value - offset) / scale 的反转换。
Q10：设备断线重连策略怎么设计的？
要点：指数退避：3 次失败判离线，退避时间 2^(failures-1) 秒，上限 30 秒。成功一次立即恢复。
你的代码：DeviceState.cs 完整实现了 ShouldSkip() + RecordSuccess() + RecordFailure() + GetBackoffSeconds()。
额外加分："为什么用指数退避？因为网络抖动可能是瞬时的，线性重试不能自适应；指数退避能自动平衡响应速度和网络压力。"
Q11：上位机离线存储的需求——你做了什么方案？
要点：客户保密要求不允许设备联网，所以数据必须本地存储。
你的代码：DatabaseManager 支持 SQLite（开发/离线场景）和 SQL Server（生产/联网场景），通过 DatabaseType 枚举一键切换。
建表覆盖：生产数据表、报警历史表、配方表、操作日志表，全部带索引。支持 BulkInsert 高性能批量写入。

⚡ 高阶：欧姆龙 FINS（学长现在用的，必补）

Q12：FINS 协议和 Modbus 有什么区别？
要点（面试前速记）：
• FINS 是欧姆龙自有协议，Modbus 是开放标准
• FINS 帧头：ICF | RSV | GCT | DNA | DA1 | DA2 | SNA | SA1 | SA2 | SID（10 字节命令头）
• FINS 支持网络路由（跨网段访问 = DNA/DA1/DA2 字段），Modbus 没有
• FINS 命令码举例：01 01 = 读 CIO区，01 02 = 写 CIO区，01 03 = 读 DM区
• FINS 可以用 UDP（速度快但不可靠）或 TCP（可靠）
Q13：欧姆龙 CP2E 的地址区有哪些？
CIO（控制 IO = 类似西门子 I/Q）、WR（工作位 = 类似 M）、HR（保持位 = 断电保持）、DM（数据存储器 = 类似 DB）。
面试诚实话术："我目前主要做了 Modbus 和西门子 S7，FINS 协议的原理研究过，但还没有实际对接过欧姆龙 PLC。如果入职，我可以在 1-2 周内用同样的分层架构（协议层+传输层+UI层）把 FINS 通讯模块搭起来。实际上 FINS 的帧结构比 Modbus 更规整，实现起来反而是比较容易的。"
Q14：西门子 S7 通讯的握手流程是怎样的？
要点：ISO-on-TCP（RFC 1006）→ 三级握手：① TCP 连接建立 ② COTP CR/CC（Transport 连接）③ S7 Setup Communication（PDU 长度协商）→ 然后才能读写。
你说："Sharp7 帮我封装了这些握手细节，但我理解整个流程：TCP 建连后先发 COTP 连接请求、再发 S7 Setup 协商双方能接受的最大 PDU 大小，然后发读写请求。"
加分项：S7 的 ReadArea/WriteArea 参数中 TransportSize（字节/字/位）的选择。
Q15：你项目的前后端架构——如果让做 Web 上位机呢？
你可以说的："我之前是前端程序员，做过 Web 开发。Web 上位机优势是多终端（不需要专用软件）、开发迭代快速、跨平台。劣势是 Node.js 做 plc 通讯延迟不如 C# 原生。如果需要，我可以用 Electron + TypeScript + C# 后端 混编架构——C# 做通讯层，Web 做 UI 层。"
这刚好匹配学长说「如果你上位机通讯 UI 监控数据什么没有问题，也可以使用西门子」
