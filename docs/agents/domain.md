# 领域文档

工程 Skill 在探索代码库时应如何消费本仓库的领域文档。

## 探索前先阅读

- **`CONTEXT.md`** — 项目根目录下
- **`docs/adr/`** — 读取与你即将处理区域相关的 ADR

如果这些文件不存在，**静静跳过**。不要标记它们缺失，也不要主动建议创建它们。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── Project/
```

## 使用术语表中的词汇

当你的输出涉及某个领域概念时（Issue 标题、重构提议、假设、测试名），使用 `CONTEXT.md` 中定义的原词。不要使用术语表明确排除的同义词。

如果需要的概念不在术语表中，这是一个信号——要么你在发明项目不用的语言（重新考虑），要么存在真正的缺口（记录以供 `/grill-with-docs` 补充）。

## 标记 ADR 冲突

如果输出与现有 ADR 矛盾，请明确提出来，不要默默地覆盖：

> _与 ADR-0007 (xxx) 矛盾 — 但值得重新讨论，因为……_
