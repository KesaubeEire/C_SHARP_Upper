📦 1. D01_1_ThreadApp — Thread 基础

课程教了什么

用 Thread 类创建后台线程执行耗时任务。关键代码：

Thread thread = new Thread(() =>
{
    for (int i = 1; i < 20; i++)
    {
        Console.WriteLine((num + i) + "  ");
        Thread.Sleep(600);   // 模拟耗时操作
    }
});
thread.IsBackground = true;  // 后台线程：主窗口关闭时自动终止
thread.Start();

教学亮点：讲解了前台线程 vs 后台线程的区别——程序在所有前台线程结束后才退出，后台线程随着进程关闭而自动终止。课程注释里也写到了"托管线程(Thread) ≠ 操作系统真实线程(ProcessThread)"的逻辑映射关系。

⚠️ 已过时的做法：Thread.Sleep() 和手动 new Thread() 在 .NET Core 时代不推荐了。Thread 对象占用约 1MB 栈空间，大量创建浪费内存。现代用 Task/ThreadPool 替代。

📦 2. D01_1_AsyncProgram — 异步回调（BeginInvoke/EndInvoke）

课程教了什么

基于委托的 BeginInvoke / EndInvoke 实现异步调用，使用 IAsyncResult 模式和回调函数 AsyncCallback：

// 定义一个委托
private Func<int, int> Operation = (num) =>
{
    Thread.Sleep(random.Next(5) * 1000);
    return num * num;
};

// 异步调用：不阻塞当前线程，完成后回调 AutoCallBack
Operation.BeginInvoke(i * 10, AutoCallBack, i);

// 回调函数中通过 EndInvoke 取结果
private void AutoCallBack(IAsyncResult result)
{
    int res = Operation.EndInvoke(result);   // 获取返回值
    Console.WriteLine($"第{result.AsyncState}个计算结果：{res}");
}

课程教了 APM 模式（Asynchronous Programming Model）—— .NET Framework 1.0 时代的异步编程范式。

❌ 已废弃：BeginInvoke/EndInvoke 是 .NET Framework 时代的 APM 模式，.NET Core 不再支持委托的 BeginInvoke（会抛出 PlatformNotSupportedException）。现代替代方案：Task.Run() + await。

📦 3. D01_3_CrossThread — 跨线程访问 UI 控件

课程教了什么

WinForms 不允许非 UI 线程直接操作控件。课程演示了 Control.InvokeRequired + Control.Invoke 的正确跨线程更新 UI 方式：

Thread thread = new Thread(() =>
{
    for (int i = 1; i < 10; i++)
    {
        num += i;
        // 判断是否需要封送到 UI 线程
        if (this.lblResult1.InvokeRequired)
        {
            this.lblResult1.Invoke(
                new Action<string>(s => { this.lblResult1.Text = s; })
                , num.ToString());
        }
        Thread.Sleep(300);
    }
});

教学亮点：这里的 Action<string> + Lambda + Invoke 组合是 WinForms 跨线程操作的标准范式，今天仍然有效且正确。

👌 仍然适用，但有更简洁的扩展方法： 
// 推荐封装成扩展方法
public static void InvokeIfRequired(this Control c, Action action)
{
    if (c.InvokeRequired) c.Invoke(action);
    else action();
}
// 使用：一行搞定
this.lblResult1.InvokeIfRequired(() => this.lblResult1.Text = num.ToString());

📦 4. D01_4_CrossThreadDataBase — 跨线程访问数据库

课程教了什么

后台线程查询 SQL Server，再把结果通过 Invoke 展示到 DataGridView：

Thread thread = new Thread(() =>
{
    DataSet ds = SQLHelper.GetDataSet(
        "select * from StudentClass;select StudentName,StudentId,Age from Students");
    Thread.Sleep(2000);
    this.dgv1.Invoke(new Action<DataTable>(t => {
        this.dgv1.DataSource = t;
    }), ds.Tables[0]);
});
thread.IsBackground = true;
thread.Start();

还用到了课程自带的 SQLHelper 类（手写 ADO.NET + SqlDataAdapter + DataSet）。

⚠️ 两个过时点：
① DataSet / DataTable 在 .NET Core 中虽然有但很少用了——现代上位机直接查出来转 List<T> 或 record
② 手动 new Thread() 可换成 Task.Run + async/await + 数据库异步方法（ExecuteReaderAsync 等）

📦 5. D01_5_ThreadLifeCycle — 线程生命周期

课程教了什么

源码中的按钮命名暗示了教学内容：Start → Suspend → Resume → Interrupt → Abort → Join。这是 .NET Framework 时代的线程状态管理：

方法作用现在还能用吗
Thread.Start()启动线程✅ 还能用，但不推荐手工管理
Thread.Suspend()挂起线程❌ .NET Core 不支持，抛 PNSE
Thread.Resume()恢复线程❌ .NET Core 不支持，抛 PNSE
Thread.Abort()强制终止线程❌ .NET 5+ 废弃，抛 PNSE
Thread.Interrupt()中断 WaitSleepJoin 状态⚠️ 还能用但不推荐
Thread.Join()等待线程完成✅ 能用，但 await 更优雅
❌ Suspend/Resume/Abort 全部过时：Suspend 可能在持锁时挂起导致死锁；Abort 可能破坏状态导致不可预料的后果。现代替代：CancellationToken 协作式取消 + await Task。

📦 6. D01_6_OtherTypeThread — 线程池 / Task / Parallel

课程教了什么 — 5 种"其他"多线程方式

这是课程最"先进"的模块，已经触及了 Task 和 Parallel：

方式① ThreadPool 
ThreadPool.QueueUserWorkItem(
    i => { Method1(); });

线程池复用线程，避免反复创建开销。但无返回值、无法 await。

方式② Task（手动 Start） 
Task task1 = new Task(Method1);
task1.Start();

比 Thread 好但没必要两行——用 Task.Run 一行搞定。

方式③ TaskFactory 
Task.Factory.StartNew(Method1);

工厂模式创建 Task。现代推荐 Task.Run 更简洁。

方式④ Parallel.Invoke 
Parallel.Invoke(Method1, Method2);

并行执行多个委托，等全部完成才返回。CPU密集型适合。

方式⑤ Parallel.For 
Parallel.For(1, 11, i => Dowork(i));

并行 for 循环。适合 CPU 密集型批处理，IO 密集型别用。

👌 课程最接近现代的部分：Task 和 Parallel 至今有效。但课程缺少最关键的一块——async/await（第29次课才讲）。上位机日常开发中最常用的 async/await 这套课没放一起。

🚀 7. .NET 10 现代异步编程演进 重点补充

7.1 async/await — 上位机的日常语言

课程第24次课没讲 async/await（放在第29次课了）。但这是现代上位机最最核心的异步方式：

// 上位机采集：用 async/await 替代 Thread.Sleep + 手动 Thread
private async void btnStart_Click(object sender, EventArgs e)
{
    btnStart.Enabled = false;
    try
    {
        await Task.Run(() => ReadPlcData());     // 后台采集
        this.lblResult1.Text = "采集完成";        // 自动回到UI线程
    }
    catch (Exception ex)
    {
        MessageBox.Show($"设备通信异常: {ex.Message}");
    }
    btnStart.Enabled = true;
}

// 或者用真正的异步IO（比 Task.Run 更好）
private async Task ReadPlcDataAsync()
{
    using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
    byte[] frame = BuildModbusFrame();
    await _sp.BaseStream.WriteAsync(frame, cts.Token);   // 真异步IO
    byte[] resp = new byte[256];
    int len = await _sp.BaseStream.ReadAsync(resp, cts.Token);
    ParseModbusResponse(resp.AsSpan(0, len));
}

核心价值：不占线程、不卡UI、异常在 try-catch 里自然捕获、CancellationToken 优雅取消。比 Thread.Sleep + Invoke 的组合好太多。

7.2 Channel<T> — 生产者-消费者新模式（.NET Core 3+）

课程讲的生产者-消费者用 ConcurrentQueue + ManualResetEvent 手动实现。现代用 System.Threading.Channels 一行搞定：

// 生产者：串口数据接收线程
Channel<PlcDataPoint> _channel = Channel.CreateBounded<PlcDataPoint>(1000);

private async void Sp_DataReceived(object sender, SerialDataReceivedEventArgs e)
{
    var dp = ReadPlcRegister();
    await _channel.Writer.WriteAsync(dp);   // 缓冲区满自动等待
}

// 消费者：UI处理线程
private async Task ProcessLoopAsync()
{
    await foreach (var dp in _channel.Reader.ReadAllAsync())  // C# 8+ IAsyncEnumerable
    {
        this.InvokeIfRequired(() => UpdateChart(dp));
    }
}

为什么比手动 Thread 好：有界容量自动背压、await foreach 自然等待、内存占用可控。

7.3 CancellationToken — 优雅取消替代 Thread.Abort

private CancellationTokenSource? _cts;

private async void btnStart_Click(object sender, EventArgs e)
{
    _cts = new CancellationTokenSource();
    try
    {
        await Task.Run(() => MonitorLoop(_cts.Token), _cts.Token);
    }
    catch (OperationCanceledException) { /* 预期中的取消 */ }
}

private void btnStop_Click(object sender, EventArgs e)
{
    _cts?.Cancel();  // 不抛异常、不杀线程、数据安全
}

7.4 ValueTask — 零分配异步（C# 7+）

当异步操作大概率同步完成时（比如缓存命中），ValueTask 避免 Task 堆分配：

public async ValueTask<string> GetPlcStatusAsync(int deviceId)
{
    if (_cache.TryGetValue(deviceId, out var status))
        return status;                          // 同步返回，零分配
    return await FetchFromPlcAsync(deviceId);   // 真异步
}

7.5 IAsyncDisposable — 异步资源释放（C# 8+）

// 串口、数据库连接等的异步关闭
await using var conn = new SqlConnection(connStr);
await conn.OpenAsync();
// ... 作用域结束自动 DisposeAsync()，不阻塞线程

7.6 Parallel.ForEachAsync — 异步并行（.NET 6+）

上位机典型场景：同时 Ping 20 台 PLC：

var addresses = new[] { "192.168.1.10", "192.168.1.11", /* ... */ };
await Parallel.ForEachAsync(addresses,
    new ParallelOptions { MaxDegreeOfParallelism = 8 },
    async (addr, ct) =>
    {
        var ok = await PingPlcAsync(addr, ct);
        UpdateDeviceStatus(addr, ok);
    });
